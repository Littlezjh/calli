# 个人 agent：跨天接续的简单版

2026-10-24 · 设计稿，未实现。

目标：agent 今天没做完的事，明天换一个会话、换一个 agent 也能接着做；需要你时找得到你，不需要时不打扰你。做法参考 [LoopX](https://github.com/loopx-project/loopx) 的思路，只取个人单机够用的部分，复用计划页、定时任务、交接和 `limi` 命令。

## 先说结论

连续性靠**事项**，不靠记忆，也不靠长对话。会话随时可以丢；事项和它的一段**接续说明**留在 Limi 里，任何会话读了就能接着做。和人有关的提醒分**三档**，只有确实需要你时才打断。

一共四样东西：

| 东西 | 是什么 | 现在有什么 |
|---|---|---|
| 事项 | 计划页的条目，加上归属、等待、到期和接续说明 | 计划页（`todos`）、关联线程 |
| 接续说明 | 每个事项一段有长度上限的文字，覆盖写，不追加 | 无 |
| 三档提醒 | 必须你决定、通知你、顺带一提 | 审批和提问（第一档）、未读 |
| 跟进时间 | 事项到时间自动发一轮 | 定时任务（只有周期性的） |

不做记忆层。偏好、地址这类长期信息由你写在个人目录的文件里，Limi 不管。

## 不依赖具体 agent

状态、触发和提醒都在 Limi 里，agent 只负责执行。哪一家 agent 都能当这个个人 agent，中途额度用完交接给另一家，事项照样接得上。

对 agent 只要求所有 coding agent 都有的东西：

| 要求 | 怎么满足 | 现状 |
|---|---|---|
| 在指定目录开会话、发一条消息 | 适配器已有 | 全部 |
| 能执行 shell 命令 | 唯一的接口是 `limi` 命令 | 全部 |
| 拿到启动时的环境变量 | `coordinationEnv`，不写 agent 配置 | 六个适配器都声明了 `capabilities.coordination` |
| 读得懂一段文字 | 入口提示和跟进模板随消息发送 | 全部 |

明确不依赖的东西：

| 功能 | 用 Limi 的 | 不依赖的原生机制 |
|---|---|---|
| 跨天状态 | 事项和接续说明 | Codex memories、Claude 自动记忆 |
| 定时与跟进 | Limi 调度器发一轮 | Claude `/loop`、Codex `/goal`、各家 hook |
| 找你 | `limi notify / wish / quiet` | 各家自己的通知 |
| 换 agent | 交接带上事项说明 | 原生会话恢复 |
| 网页与登录态 | `limi browser`（你的 Chrome） | 各家浏览器工具 |
| 借能力 | `limi tools` | 各家 MCP 配置 |
| 说明怎么用 | 入口提示 + `limi todo --help` | `AGENTS.md`、`CLAUDE.md`（各家读的文件不同） |

原生能力可以叠加使用，例如你给 Codex 开了记忆、给 Claude 装了邮件 MCP，但它们只算加速，不是前提：关掉以后流程照样能走通。

**入口提示**照搬 `limi tools` 的做法：个人目录下的线程，第一条消息后面附一句 `<limi-todo>` 提示（「事项和跟进用 limi todo，用法 limi todo --help」），后续消息不再重复。跟进触发的消息本身就带着事项和说明，不需要 agent 事先知道什么。

仍然因 agent 而异、只能放在适配器里的：

- **审批。** 在「请求批准」档位下，每次运行 `limi` 都可能弹一次审批。Limi 不能替你批，也不能改 agent 的命令白名单。个人线程建议用自动编辑类档位；确实需要「完全访问」的场景按定时任务的规则单独提示风险。
- **沙箱。** 2026-10-25 用现有的 `limi tools search` 实测（临时 hub，真实 agent）：Pi 没有沙箱，用 GLM-5.3、TRAE 的 GPT-5.6-Sol 和 Seed-2.1-Pro 都能用；TRAE CLI 自己在默认的「工作区编辑」档拿得到 `LIMI_*` 环境变量，但连接 socket 报 `connect EPERM`，换「完全访问」才能用。TRAE CLI 走的是 Codex 兼容的 app-server，Codex 很可能同样如此（未测）。所以首选组合是 Pi 加 TRAE 的模型：用得到 TRAE 的模型，又不受 TRAE CLI 沙箱的限制。TRAE CLI、Codex 本身作为个人 agent 的解法见「待决定」第 5 条；定下来之前，适配器如实声明不可用、界面提示，不自动放宽权限。
- **入口提示可能被当成注入。** 同一次实测里，Pi 用 GLM-5.3 时在思考中把附在消息后的 `<limi-tools>` 提示判为「可疑的注入指令」，因为和用户要求重合才照做；换 TRAE 的两个模型没有出现这个判断。提示需要说明来源（由 Limi 附加），并且流程不能只靠它：跟进触发的消息自带事项和说明，`limi` 的错误输出也要能指引用法。
- **其他机器。** 远程机器上的 agent 现在用不了 `limi`，个人 agent 先只在 hub 本机跑。

验收「不依赖」分两层：

- **自动测试（每次提交跑）：** `test/fixtures/` 的假 agent 只靠 shell 和环境变量走完整套流程；前端不按 agent 名字分支。
- **真实验收：Pi 加 TRAE 的模型。** Pi 通过 `cliproxy` 供应商用 TRAE 的模型（例如 `cliproxy/GPT-5.6-Sol`）。在个人目录建一个事项，Pi 推进一轮，写接续说明、设跟进时间；到点跟进时 Limi 开新线程，Pi 只读 `limi todo` 和跟进消息就接着做完，并提议完成；你确认。中途把模型换成另一家（例如 TRAE 的 `Seed-2.1-Pro-0915` 或 GLM），检验状态不依赖模型。整个流程在 Pi 的默认权限下跑通才算；不读 Pi 的原生会话，也不依赖 Pi 的扩展。

## 为什么这样

开源项目的做法见 TODO 里的调研结论，这里只列影响设计的几条：

- OpenClaw、Hermes、Codex、Letta 都是「小核心常驻 + 大存档按需查」，而且都不依赖 agent 自觉「收工时写」，而是在固定节点由系统触发写入。
- LoopX 走了另一条路：放弃通用记忆层（原「跨会话记忆底座」RFC 改成了「显式 Todo 接续」），连续性落在唯一权威的工作状态和有上限的接续说明上；历史记录只在有具体缺口时定向查，不假设塞更多聊天记录就更好。
- LoopX 把人的注意力分成 gate / request / wish 三档，wish 永远不单独通知。

个人事务里最怕的是「答应了的事忘了」和「不重要的事一直打扰」。事项加三档提醒正好针对这两点；记忆有用，但不是主干。

## 1. 事项

在现有计划项上加字段，不另建表，不复制存储：

| 字段 | 说明 |
|---|---|
| `owner` | `me`（你的承诺，例如「周五前交报销」）或 `agent`（agent 替你做的准备，例如「整理报销单据」）。旧数据默认 `me` |
| `state` | `open` / `waiting` / `done`。`waiting` 带一句 `waitingOn`（「等王五回邮件」） |
| `dueAt` | 可选，截止时间 |
| `followUpAt` | 可选，下次跟进时间，见第 4 节 |
| `rev` | 版本号，每次修改加一。agent 修改时带上读到的版本，不一致返回 409，避免旧会话覆盖你刚改的内容 |
| `proposed` | agent 建议新增的 `me` 事项，等你确认，见下 |

仍然只有一层子项。主项相当于目标，子项相当于步骤。

规则只有三条：

1. **你的事项只有你能标完成。** agent 只能提议完成，并附一句依据（链接、回复摘录）；提议以第二档提醒出现，你点一下确认。草稿写好、消息发出，不等于你的承诺已兑现。
2. **agent 新建的 `me` 事项先是建议。** 邮件里一句「你周五前给我」可能是真承诺，也可能是引用、问句或别人的事；也可能是注入。建议在计划页顶部单独一组，接受或忽略。`agent` 事项 agent 可以直接建。
3. **改动要带版本号。** agent（`limi` 命令）必须带，不一致返回 409，也就是先读后写；网页上你自己改可以不带，按当前版本覆盖并递增。

不做：LoopX 的 claim / lease、证据账本、多 agent 认领。单人单机，同一事项同时只有一个会话在推进，冲突靠版本号发现。

## 2. 接续说明

每个事项一段，最多 4000 字符，覆盖写。固定四个小标题，取自 LoopX 续接说明的六个问题，合并成四个：

```markdown
## 欠谁什么
## 定了什么（包括否决的路线和原因）
## 做到哪（已完成的、可能仍在执行的，比如已提交但未确认的表单）
## 下一步
```

谁来写、什么时候写：

- **agent 在改了事项的那一轮结束前写。** 用法写在 `limi todo --help`，由入口提示引出，不依赖各家的说明文件。
- **交接时 Limi 提醒写。** 交接内容里列出这条线程关联的事项和它们当前的说明，接手方读到的就是最新状态。这是现有交接的扩展，不改交接流程。
- 写不写不由 Limi 保证。没写的，下一个会话看到的是上一版说明；关联线程只是记录，不去读它们的历史（`limi history` 只用于交接链）。说明标注最后更新时间和写入的线程，过时一眼可见。

不做：上下文压缩前自动触发写入。各家 agent 的压缩不在 Limi 控制内。

## 3. 三档提醒

| 档 | 什么时候用 | 呈现 | 现在 |
|---|---|---|---|
| 必须你决定 | 付款、发送、提交、登录验证、权限 | 阻塞，线程和标题栏直接可见 | 审批、提问、计划确认已有 |
| 通知你 | 有结果要你看；事项提议完成；建议新增事项 | 线程未读 + 标题栏计数；以后接系统通知 | 未读已有，缺 agent 主动发起的入口 |
| 顺带一提 | 可选的事：「有空看一下这个默认设置」 | 不产生未读；计划页底部「顺带」一行，展开看；第二档出现时附带最多一条 | 无 |

加两个命令，作用于当前线程：

- `limi notify --text-file FILE`：第二档。线程里出现一条 agent 发起的提示（`agent.notice` 事件），线程标未读，开了推送就推。首版不新增 `attention.kind`（沿用未读）；单独的 `request` 档位会改动侧边栏和标题栏，等界面审过后再加。
- `limi wish --text-file FILE`：第三档。写到计划页，不标未读。

**安静结束。** 定时任务和跟进经常没事可做。agent 运行 `limi quiet` 表示「这次没有需要你看的」：这次运行记为 `quiet`，线程不标未读，`new` 模式的运行线程自动归档。没调用就按现在的行为处理。用显式命令而不是从回复内容猜，误判的代价是你错过一件事。

系统通知（Web Push、飞书或 BotMux）是独立的出口问题，见 TODO 第 5、6 节。三档定下来之后，出口只需要推第一、二档。

## 4. 跟进时间

事项的 `followUpAt` 到了，调度器发一轮，复用定时任务的执行和运行记录：

- 事项关联了线程：发到最近关联的那个线程（线程还在、没在运行时）；否则在个人目录新开线程并关联到事项。
- 发送的提示词是固定模板：事项标题、当前状态、接续说明，以及「处理完更新说明；没有进展就设下次跟进时间并 `limi quiet`」。
- 跟进后 `followUpAt` 清空，要再跟进由 agent 重新设。不会每天重复轰炸。
- **防空转：** 同一事项连续 3 次由 Limi 发起的跟进结束后，接续说明都没有变化，就不再自动跟进：清空跟进时间，在最近关联的线程记一条通知（走推送），写明「连续 3 次跟进没有进展，已停止自动跟进」。agent 之后再设跟进时间会被拒绝，直到你在网页上重新设，或说明有了变化。你或 agent 改动说明、你手动设跟进时间，都把计数清零。计数存在 SQLite，重启不丢。
- 线程正在运行时推迟到这轮结束；daemon 停机错过的，启动后补一次。

周期性的事（每天早上汇总）仍然用现有定时任务。不做 agent 自建周期任务。

## 5. 个人目录

默认个人目录是 `~/.limi/personal`，首次需要时自动创建（新建目录权限为 0700，已存在的不改权限），可以在私人设置里改为允许的工作目录。默认目录不允许是指向别处的符号链接。生效的个人目录及其子目录自动允许使用，但不加入「可用目录」列表，也不修改 `RAH_WORKDIRS`。

未指定 agent 时优先使用可用的 Pi 实例，否则使用第一个可用实例；模型留空。也可以在私人设置里选择 agent 和模型，例如 Pi 加 TRAE 的模型。第一次「交给 agent」直接使用这些默认值，只有没有可用实例时才需要先设置：

- 只有工作目录在这里的线程能用 `limi todo / wish`（同 `limi tools` 的做法：环境变量里的 socket 和 key）。别的线程，例如写代码的线程，看不到你的个人事项。`limi notify / quiet` 只影响调用者自己的线程，所有线程都能用。
- 跟进需要新开线程时，用这里的 agent 和模型，权限取该 agent 的默认档位；有可用的旧关联线程时沿用它的 agent、模型和权限。
- 跟进新开的线程、个人类定时任务默认用这个目录。
- 目录里的文件由你写，Limi 不生成、不修改。想让各家都读到偏好，可以写一份 `AGENTS.md`，再按需加 `CLAUDE.md` 引用它；这是可选的，流程不靠它。

凭证只在 hub 本机的线程里有。其他机器上的线程用不了，和现在 `limi` 的限制一致。

## 6. 盘点：自己定时唤醒自己

跟进只管设了跟进时间的事项；没交出去、没设跟进的事项没人看。盘点补上这一块：私人 agent 定期把计划过一遍，只读、只问，不自己开工，并自己决定下次什么时候再看。

- **开关：** 默认关。在私人目录的线程里对 agent 说「开启盘点」，它运行 `limi review on`；以后私人设置弹窗加一行开关（界面待审）。
- **唤醒：** Limi 在 `nextReviewAt` 到点时，在个人目录新开一个「盘点」线程，用私人设置的 agent 和模型，发盘点模板。同一时间只跑一个盘点。
- **自己定下次：** 盘点结束前，agent 用 `limi review next TIME` 定下次时间，依据最近的截止、跟进、等待和你的回复节奏。限制：至少 30 分钟后、最多 3 天后；落在安静时段（默认 23:00–08:00，daemon 本地时区）就顺延到安静时段结束；每天最多 4 次。没定就默认下一个 09:00。
- **盘点做什么：** 读未完成事项（标题、状态、等待、截止、跟进、说明的「下一步」、关联线程是否在跑），然后：
  - 笼统的事：提 1～3 个具体问题，每个附建议默认；
  - 挑今天最值得做的 1～2 件，问要不要开始；
  - 卡住、逾期、停止跟进的：提醒；
  - 以上合成一条 `limi notify`（不超过 500 字），一次盘点最多推一条；
  - 没有需要你的：`limi quiet`，线程自动归档。
- **你怎么回：** 在盘点线程里直接回复。agent 按回答更新事项（写说明、设等待或跟进）；你说「开始 X」时，它用 `limi todo delegate ID` 把那件事交出去，等同于你在计划页点「交给 agent」（新开私人对话）。盘点线程本身不做事项的实际工作。
- **安全：** 盘点不做不可逆操作；`delegate` 只在你明确说开始之后调用；连续 3 次盘点都没有推送且没有你的回复，下次间隔自动拉长到至少 1 天。

## 命令

```bash
limi todo                          # 未完成的事项：标题、owner、state、到期、跟进、说明首行
limi todo show ID                  # 一个事项的全部字段和完整说明
limi todo add --owner agent|me --text-file FILE [--parent ID] [--due TIME]
limi todo update ID --rev N [--state open|waiting|done] [--waiting-on TEXT]
                            [--due TIME] [--follow-up TIME] [--note-file FILE]
limi todo propose-done ID --rev N --evidence-file FILE
limi notify --text-file FILE
limi wish --text-file FILE
limi quiet
limi review on|off|status
limi review next TIME
limi todo delegate ID
```

`FILE` 可以是 `-`。时间接受 ISO 8601，不带时区时按 daemon 本地时区。`me` 事项不能 `--state done`，返回 403 并提示用 `propose-done`。`add --owner me` 生成的是建议。

## 接口

- `GET /api/todos` 返回新增字段和说明的首行、更新时间；完整说明 `GET /api/todos/:id/note` 展开时才读。
- `PATCH /api/todos/:id` 接受新字段；`PUT /api/todos/:id/note`。界面的修改可以带 `rev`，带了就校验。
- `POST /api/todos/:id/proposals/:pid/accept|dismiss`：处理完成提议和新增建议。
- `GET / PUT /api/personal/settings`：个人目录、默认 agent、可选的模型。
- agent 走单独的 socket，按线程授权，只开放上面列出的操作。

## 界面

私人入口在计划页（草图 ⑤⑥，待审），不加菜单项、不占侧边栏：

- 计划页最后一行输入框照旧，回车只记一条计划；输入时右侧出现「交给 agent」：记下这条计划，按私人设置开一个对话把它交过去，事项自动关联对话。
- 说明下面一行显示当前私人设置（目录 · agent · 模型），点它改设置；还没设置时，第一次「交给 agent」先弹出设置。
- 已有的事项上也有「交给 agent」（悬停或手机点开时出现）；已有进行中对话的事项不显示，改显示对话标签。
- 私人对话在侧边栏归在「私人」一组。

计划页在现有页面上加，不新开页面：

- 每行：归属用小图标区分（你 / agent），到期和等待用短文字，逾期才用注意色。截止、等待、跟进用淡色短字，逾期才用注意色。接续说明默认完全收起，行尾只有一个淡色小图标；点行或图标才读取并展开，展开后缩进显示、只用左侧细线，「下一步」排在最前，再点收起。
- 顶部「待你确认」一组：完成提议和新增建议，各一行，接受 / 忽略两个按钮。没有就不出现。
- 底部「顺带 N 条」，默认收起。
- 线程头部显示关联事项的标题，点击跳到计划页对应行。
- 手机：同样的信息，点开看详情；接受和忽略按钮与展开详情分开。

文字进 `i18n/locales`，颜色只用 `styles.css` 变量。

## 安全

- 邮件、网页里的内容不能直接变成你的事项，也不能把事项标完成；只能变成建议和提议，由你确认。
- 说明里不写密码和验证码。`limi todo` 写入时拒绝明显的凭据格式（私钥、常见 token 前缀）；Limi 现在没有脱敏规则，这里要新写，只做明显格式，不承诺拦住全部。
- 个人目录之外的线程拿不到事项凭证。

## 不做

- 记忆层、记忆检索、记忆效用评估。
- LoopX 的目标层级、认领与租约、证据账本、额度调度（`quota should-run`）。
- 多人、多机器共享事项。
- 从邮件、飞书自动抓取承诺。agent 读到了可以提建议，Limi 不做采集。

需要这些时，接 LoopX：它已经是 Limi 的工作数据源，事项状态可以以 LoopX 为准。

## 分步

1. 事项字段、接续说明、界面（不涉及 agent）。你先手动用几天，看字段够不够。
2. 个人目录、事项凭证、`limi todo`、建议与提议。
3. `limi notify / wish / quiet`，定时任务的 `quiet` 状态。
4. 跟进时间；交接内容带上关联事项的说明。

每一步：新接口有测试；`limi` 命令走真实 daemon 的集成测试；界面在桌面和手机、亮色和深色下看过。

## 待决定

1. **计划页原来定了「不做截止时间、提醒、让 agent 改清单」**。这份设计推翻了这三条，事项进核心，而不是走扩展。理由：它和交接、定时任务是同一条主线，`limi` 命令也已经在核心里。
2. 个人目录只允许一个，还是可以多个。
3. `me` 事项的建议是否需要确认。只读邮件做汇总时，建议会比较多；可以先确认，用一段时间后再看要不要放宽。
4. 个人线程的默认权限档位。档位太低，每次 `limi` 都要审批；太高，读邮件的 agent 也能直接执行命令。
5. TRAE CLI（可能还有 Codex）默认档的沙箱挡住了 `limi` 的 socket。三个方向：一是适配器只为这个会话打开沙箱的本机网络访问（类似借用搜索时只为那个会话开 `web_search`，不改用户配置），代价是 agent 的命令也能联网；二是个人线程默认用完全访问，风险最大；三是 TRAE 和 Codex 暂不支持当个人 agent。倾向第一个，需要先确认 app-server 能不能只放行本机 socket。
