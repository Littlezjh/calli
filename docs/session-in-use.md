# 会话被其他应用占用

采用用户提供的 Codex 截图：输入区显示中性的锁定提示，说明“已在另一个应用中打开”，提供“重试”和“创建聊天分叉”。手机将操作放在说明下方。沿用现有分叉流程；不支持分叉的适配器不显示分叉按钮。

## 判断与恢复

- Codex 适配器识别原生错误 `thread … already has an active writer`，由服务端记录为 `session_in_use`。恢复会话失败与发送轮次失败都覆盖。历史更新、普通文件锁、另一个线程忙碌、模型额度不足不会被归入此类。
- 失败码随轮次保留，刷新后重新打开会话仍能显示。前端使用失败码，不按 agent 名称或英文错误文字判断。
- 占用期间收起输入框、暂停排队消息，保留已有内容。重试先正常恢复会话；仍被占用时保持提示，不新增提交；释放后继续失败的请求，再发送队列。
- 分叉调用已有接口，复制历史并创建独立会话，原会话继续保留。不会强行抢占、删除锁文件或终止其他应用。
- 当前占用提示集中显示在输入区，历史中的旧占用记录用中性色显示。

## 验证依据

本机 Codex CLI 0.167.2，两个使用同一临时目录的独立 app-server：第二个进程恢复时返回原生写占用错误；原持有者未退出时可以分叉；原持有者退出后正常恢复成功。测试使用隔离的配置目录与本地测试 provider，不修改用户会话，也不调用外部模型。

自动回归见 `packages/daemon/test/session-in-use.test.ts` 与 `packages/e2e/test/session-in-use.spec.mjs`。接口依据见 [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。
