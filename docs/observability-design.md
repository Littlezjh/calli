# 用量统计与 Agent 诊断

入口在「配置 → 用量与诊断」。模型列表为空时的「检查实例」直达诊断页，诊断成功后的模型列表同步回选择器。各机器只统计自己接收到的执行；远程机器通过已有代理访问相同接口，需要更新该机器的 daemon。

## 用量口径

上下文占用、模型消耗和套餐额度是三种不同数据。原有 `usage.updated` 仍表示上下文；新增 `usage.sample` 表示原生用量，不能从上下文、字符数或历史对话估算消耗。未知字段保留未知，不补零。

| 接入 | 来源 | 粒度与限制 |
| --- | --- | --- |
| pi | `message_end` 的 assistant usage | 每次模型回复；记录输入、输出、缓存读写、推理（原生提供时）、总 token、原生估算费用、模型与 provider。输入归一为普通输入加缓存读写。首 token 延迟从原生请求时间戳到首个文本、思考或工具片段；没有时间戳则未知 |
| Codex / TraeX | `thread/tokenUsage/updated` | 原生累计值增量；初次通知只取 `last`，不将恢复前的累计历史记进来。重复通知忽略，计数下降时重设基线。通知可能合并多次调用，明确标为「用量增量」，不宣称逐次请求 |
| Claude Code | 当前会话 JSONL 及其 `subagents/`，轮末以 ACP usage 补差 | 每 2 秒读取新增字节，同一 message ID 的内容块去重，后续修订只记新增计数；子 Agent 同样去重。缓存与普通输入归一。结束、取消、错误时补读；文件不可读时回退整轮协议汇总。协议总数与已读请求对账，只补尚未记入的字段与数量 |
| 其他 ACP | `session/prompt` 的 usage、`_meta.quota.model_usage` | 有按模型拆分时优先使用，不再加主循环 token；整轮 token 按执行时段平摊并标明时间估算。费用仅在连续收到同币种累计费用、且本轮报告新读数时作差；恢复后没有基线的费用未知，费用独立记录，不错误分配给单个模型 |
| zcode | 优先检查 `session/usage` 的口径；必要时只读会话数据库 `model_usage` | 提供原生消耗累计值的版本每 2 秒作差，结束时补读。本机版本返回 `inputBaselineBySource`，会扣除重复输入，不能用作模型消耗；这类版本读本轮的原生请求行，保留模型、provider、延迟与缓存明细。数据库只读、不迁移，失败保留已记数据，缺口未知。支持默认数据库位置和实例的 `ZCODE_SESSION_DB_PATH`；自定义配置路径须通过此环境变量明确指定 |
| agy | 当前会话 `transcript.jsonl` 的 `PLANNER_RESPONSE` | 流未提供 token，因而每 2 秒读取本轮追加的原生输入、输出、缓存字段；按 step 与时间戳去重。文件缺失或格式不识别保持未知，不扫描其他会话或调用上游接口 |

「所选模型」「实例账号」是轮次开始时的配置快照，不等于上游实际模型或账号。只有原生明确报告时才填写实际模型、provider 和上游账号。Limi 未代理模型 API，因此不能声称知道供应商内部的路由账号。费用沿用原生估算，未引入静态价格表；不同币种分开合计。已报告费用和 token 合计可能只覆盖部分执行。

TPM 是 token/分钟，K、M、B 分别表示千、百万、十亿。看板支持「合计 token」与「仅输出 token」：合计含缓存读取，可能远大于模型生成速度；它不是供应商限流额度。最近 1 小时、24 小时、7 天分别使用 1、10、60 分钟的时钟对齐桶，桶中显示平均 TPM。合计线与每个已报告用量的实例线可独立显示／隐藏；悬停、点按、方向键和数值表都可读数。旧 daemon 未提供新字段时兼容显示已有数据。

会话文件／轮末批量汇总采用相邻报告之间的时间区间平摊；zcode 请求行使用原生请求起止时间。token 数量仍是测量值，区间内的时间分布是估算，会明确标注，绝不根据字符数或运行时长凭空增加 token。Codex、TraeX、pi 的原有实时协议记录继续按到达时刻入账。总量卡片按入账时刻筛选，走势图按估算区间裁剪，跨查询边界时两者不一定相等；旧记录不回填时间区间。

尚未完成或尚未落盘的模型请求仍可能没有用量，不能保证运行中 TPM 始终非零；空闲超过一分钟后为 0。所选范围没有任何可测量数据时显示未知。看板每 10 秒刷新，后台页暂停轮询。采集仅在当前 hub 轮次执行期间进行，开始前记录文件末尾位置，不读取历史正文；恢复使用实例自己的配置目录与会话 ID，不修改 Agent 配置、不安装 hook、不上传统计。

文件读取使用异步分块，每次轮询每文件最多读 4 MiB，结束时补读剩余数据；单条超过 2 MiB 或不符合格式的记录跳过，Claude 仍可由协议汇总补差。读取失败不清空已记数据。缓存误计入输出仅在另一个原生总数能证实重叠时纠正，不按数值大小猜测。若文件总数已大于协议总数，保留原生请求读数，不倒扣已经入账的记录。

每轮「首段输出等待」从发送到首个文本或思考事件，包含 CLI 启动和工具等待，不能用作上游 TTFT。请求级延迟只有原生协议足以测量时才展示。整轮错误与原生请求错误分别保留。

## 存储与接口

- `telemetry_turns` 保存实例、所选模型、实例账号、开始/结束、首段输出等待与状态。
- `telemetry_samples` 保存用量；按线程、轮次、原生样本 ID 去重。SQLite 与事件日志同库，重启保留；永久删除线程级联清理。
- 只记录启用后的实时执行，不回填导入/终端同步，也不复制分叉来源的用量。
- `GET /api/usage?hours=1|24|168&agent=`：所选时段合计、当前 TPM、输出 TPM、时钟对齐的总计／实例曲线、最近 100 轮及原生明细，归档线程也计入。新增字段兼容旧客户端。
- `GET /api/agents/:id/diagnostics?refresh=1`：CLI/桥接程序版本、接入协议、模型读取状态、检查时间、模型列表及适配器声明的能力。

诊断按实例缓存一分钟，并发刷新共用一次检查；显式刷新清除适配器模型缓存。模型读取成功不等于供应商接受付费调用，不发送试探提示词。CLI 缺失、空模型、认证错误、协议不兼容、超时和其他读取失败分别呈现；无法可靠判断原因时保留通用读取失败。诊断不返回环境变量、凭据或原始错误文本。模型探测有超时并清理自身进程，不关闭正在执行的会话。

## 验证

`telemetry.test.ts` 覆盖累计与恢复、去重、计数回退、缓存口径、跨币种、TPM 窗口、实例筛选、持久化、导入/分叉排除和删除清理。`observability-api.test.ts` 用假 CLI 验证四种原生协议的实际交互，并验证接口鉴权、错误分类、刷新与并发复用。`observability.spec.mjs` 覆盖桌面/手机 × 亮/暗，用量明细、诊断刷新和复制。


查询将样本解析一次、按轮次分组，避免为每个最近轮次扫描全部样本。使用 600 轮 × 50 次请求的合成数据，本机测得 24 小时查询约 24ms、7 天约 164ms（原实现 7 天约 609ms）；不是线上性能保证。

新增 `live-usage.test.ts` 覆盖部分行、重复块、修订、子 Agent、文件截断、缺失／格式错误、取消和协议补差。假 Claude、agy、zcode 均生成对应原生记录；真实 zcode 通过隔离数据目录与本地模型服务验证轮中读取及重复输入口径，不使用付费模型。浏览器回归覆盖多线选择、输出切换、键盘／触屏读数、数值表和四种尺寸／主题组合；真机触控未验证。
