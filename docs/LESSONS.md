# 从已合入的改动里学到的

这个仓库的代码大多由 agent 写、改、合入。这里记的是：哪些改动后来又要返工，返工的那一类问题本该被哪条规则拦住。改代码前先读一遍。

每条的写法：**规则**，然后是为什么、证据（commit）和“出现天数”（在多少个不同的日子里看到同类返工）。同一条出现满 3 天，就把规则升级进 `AGENTS.md` 或测试，这里留一行“已升级”指过去，正文压成一句。

复盘方法：`git log --no-merges` 里 `fix`、`revert` 开头的提交，按“要是早知道哪条规则就不会返工”归类。复盘到哪个提交，写在第一行的 `reviewed-through`；下次从那里往后看。

## 2026-11-19 首次复盘

截至 `c1b3aa0` 共 620 个提交，其中 179 个是 fix。146 个碰了 `packages/web`，70 个碰了 `packages/daemon`。UI 返工主要是下面几类。

### 1. 布局稳定在第一版就要测，不是出了跳动再补

为什么：同一个“打开、加载、刷新时界面不跳”的要求，在不同组件上被修了一遍又一遍，每次都是用户先看见跳动。`AGENTS.md` 里早就写了“布局稳定”，但它只是文字。

证据：
- `f4d97b2`（10-10）重开线程时截图加载后把视图拉离底部
- `c239f98`（10-24）写作条在新线程上长成一大块空白卡片
- `91263bc`（10-15）、`df87d7e`（11-07）额度刷新时读数消失、布局变化
- `d2fd930`（11-08）线程概况自适应时跳动
- `e7c562b`（11-09）思考窗口高度不固定，页面跟着动
- `ab25db9`、`0ef3bb7`（11-10）概况面板高度同一天修了两次
- `60434c6`（11-10）往上翻交接链时跳回更早的轮次

出现天数：7。**已升级**：`packages/e2e/test/ui-rules.spec.mjs` 测几个核心页面加载过程中不跳、不横向溢出、点击不滚动。新页面或新的异步区域要加进 `packages/e2e/screens/catalog.mjs`。

### 2. 第一版放在明处的东西太多，事后再收进菜单和详情

为什么：新功能第一版常把入口、说明、状态都直接摆出来，过几天再一条条收进 `⋯`、折叠或设置里。每收一次就是一次返工，也让界面在这段时间里很乱。

证据：
- `40280e7`（10-23）记忆入口挪进设置
- `769f162`（10-22）用量与诊断从浮窗改成页面
- `df0440c`（10-15）运行状态简化
- `87adcde`（11-03）自动交接提示从卡片改成一行
- `e1d3563`（11-05）输入框菜单只留“设目标”
- `a9b31ae`（11-05）交接轨迹挪进线程菜单
- `6422fc1`、`eb8eecb`（11-07）输入框控件、线程菜单、额度摘要压缩
- `1a4750a`（11-08）空额度折成一行
- `1430320`（11-10）上下文面板只留摘要，其余放到“详情”后面
- `6d54292`（11-13）错误改成简短、可展开
- `499a4c2`（11-19）桌面入口挪进对话菜单

出现天数：9。**规则**：新功能的入口默认放在 `⋯`、右键菜单、`Cmd+K` 或详情里。要放到首屏，得在设计文档里写清楚“这是当前决策要用的”，并在回复里说明。

### 3. 视觉方向反复来回时，停下来做对比图，不在代码里试

为什么：材质、阴影、色带这类取舍，在代码里一个提交一个提交地试，会出现几分钟内来回改三次，或者第二天又改回去。

证据：
- 宽屏顶栏：`ccb0881`（11-08 13:50）改成实底，`b1dd1b5`（11-09 02:53）改回玻璃，`19aec96`（18 分钟后）又改成磨砂
- 输入框色带：`fdbb0d4`（11-07 12:51）延伸到窗口边，`95021d6`（5 分钟后）收回到框边，`c5f0264`（8 分钟后）改成圆形阴影
- 玻璃控件在 11-07 一天有 5 个 fix：`e08168e`、`87b30bb`、`47ec97f`、`793477f`、`b6139f6`

出现天数：3。**规则**：同一处视觉改了第二次方向，就停下来，在 `docs/design/` 做一个能并排比较方案的 playground（像 `glass-playground.html`），让人选定以后再写代码。

### 4. 手机上的触摸、键盘、输入法要按真实手机测

为什么：桌面上测通过的交互，到手机上会被软键盘、长按、手势、输入法确认键打断。

证据：
- 输入法回车误发送：`587f2c2`（10-27）、`7136662`（10-11）
- 软键盘：`5811a64`（10-10）、`040c291`（10-11）、`98879e8`（11-14）
- 长按菜单：`abcc83d`（10-27）、`6c5a002`（10-28）、`be27365`（11-12）
- 手势：`41cdf16`（11-07）、`68dc732`（11-10）
- 工具栏点击后键盘收起：`5832e41`（10-27）

出现天数：8。**规则**：改触摸、手势、输入、键盘相关代码，e2e 要用 `isMobile: true, hasTouch: true` 的上下文测；涉及输入法的，要测 `compositionstart`/`compositionend` 里按回车。

### 5. 修一个入口，要把同类入口一起修

为什么：同一个能力常有好几个入口，只修了报告里的那一个，过几天另一个入口又坏。

证据：
- 打开线程链接：`5e9b3c3`、`1bfbd36`、`12d68e9`（11-14），`556dc46`（11-19）
- “用选中的模型启动”：`e307260`（11-04），`fe2f8cd`（11-07），`c26e45f`（11-15），`27777bf`（11-16），`7d883ae`（11-17）

出现天数：6。**规则**：修入口类问题前，先 `grep` 出所有调用同一能力的地方，一次修完，测试覆盖每个入口；回复里列出查过哪些入口。

### 6. 菜单的嵌套、长按和重渲染

为什么：菜单是全站共用的交互，每个菜单各写一点开关逻辑，就会各坏各的。

证据：
- `abcc83d`（10-27）、`6c5a002`（10-28）长按打开的菜单被同一次抬手选中或关掉
- `02f21d5`（11-08）菜单渲染死循环
- `8f8b05f`（11-08）、`6fb1d67`、`580efaa`（11-09）列表菜单和线程菜单拆开、拍平、收紧
- `7e00b8f`（11-10）嵌套菜单保持打开
- `0930543`（11-10）选择器出现两条原生滚动条

出现天数：5。**规则**：菜单只用 `Menu`、`Popover`，不在业务组件里另写开关逻辑。改共用菜单时，跑一遍所有用到它的 e2e。

### 7. 测试 hub 不能碰真实环境

为什么：测试 hub 扫描了本机真实的 agent、账号和会话，结果既慢，又会在真实目录留下东西。

证据：
- `b40065e`、`091b5e9`（11-09）本地扫描和自动加入碰到真实环境
- `b9057b5`（11-10）额度探测留下 `/usage` 会话

出现天数：2。

### 8. 同一个提交进了 main 两次

证据：`4d9fa27`/`d424cd5`、`3b875db`/`35d8a85`（11-04），`87adcde`/`57cfd1f`（11-03）。标题和改动都一样，是 rebase 或 cherry-pick 后又合了原分支。

出现天数：2。**规则**：合并前用 `git log --cherry-pick --oneline main...分支` 看有没有重复。

### 9. 两个功能共用一套类名，后写的样式把先写的盖掉

为什么：类名是全局的，样式表按文件顺序生效。后加的功能（助手「未来时段」面板，`c50ffb6`）复用了对话计划段的 `.plan-list`/`.plan-text`，它靠后的「边框卡片」规则把 `dcf84b5` 设计的安静细线列表整个盖掉，十天后才被当作「丑」报出来——期间没人知道样子是被串味改的，还差点当成新的视觉方向去改稿。

证据：`dcf84b5`（11-03，安静计划行）→ `c50ffb6`（11-09，面板复用类名）→ 11-19 用户报「计划的样式太丑」，根因是串味不是设计。

出现天数：1。**规则**：给界面上样式前，先 `grep` 类名有没有别的功能在用；面板类组件的规则一律收在自己根类名的名下（如 `.plan-view .plan-list`），不写全局类。`packages/web/test/plan-styles.test.ts` 守住这一条。
