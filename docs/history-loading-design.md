# 历史正文优先与详情按需加载

状态：已实现。主对话、协作成员和侧聊统一使用摘要历史与按需详情。

## 目标与判断

贯彻「一眼看出大概，详情继续点开」：渐进展示同时约束界面、网络和数据库读取。默认折叠的重内容不应在打开线程时下载、解析和构建。

方案可行，属于中等规模改造。统一事件已经覆盖各 agent，工作记录、工具详情和文件 diff 也已有展开入口；无需改变 agent 的配置、目录或会话。主要工作是建立轻量读取模型、接入共用加载逻辑，以及处理旧数据和实时续传的一致性。

覆盖主对话、协作成员对话、侧聊及其所有 agent。首次从原生 agent 导入会话仍受其历史接口限制；本方案优化 Hub 已保存内容的读取，不承诺原生导入也能即时完成。

## 改造前的限制

- `Store.iterateEventsPage` 按最近最多 3 轮、2,000 条事件预算读完整轮次，超长单轮仍全部读出。
- `ThreadManager.listEventsPage` 合并工具快照与文字增量，但仍解析原始工具载荷并发送最终完整内容。
- `ThreadView` 的工作块、工具行和文件改动只是条件渲染，展开时没有请求；折叠不减少下载。
- `App`、`AgentPanel`、`SideChat` 各自加载历史和订阅 SSE。现有 SSE 重连补传完整事件，单改首屏接口会被续传抵消。
- `turn_text` 拼接一轮内全部 `message.delta`，包含中途说明，不能直接当作最终回答。`trace` 有截断和不同的分组语义，也不能直接用作完整详情接口。
- 文件增删统计现在由前端解析完整 diff 得到，拆分后需要由后端提供统计。

## 展示与加载层级

| 层级 | 何时加载 | 内容 |
| --- | --- | --- |
| 正文与概况 | 打开线程、向上翻页 | 用户问题、回答正文、计划正文、附件引用、工作块耗时与步骤数、文件改动统计、结束状态、错误、交接和分叉标记 |
| 工作记录 | 展开对应工作块 | 有序步骤标题、状态、时间、中途说明、思考预览和压缩记录；不带工具参数、输出或 diff 正文 |
| 单项详情 | 展开工具、思考或文件 | 对应工具参数和输出、完整思考、该文件的 diff；超大内容分段读取并明确提示还有内容 |

默认取最近 8 轮，保持时间顺序，首次定位到最新回答。向上翻页继续取 8 轮，长回答完整保留。当前按轮数限制，不截断正文；额外的正文体积预算留待长正文数据验证后调整。工作记录每页 100 个条目，工具输出与完整思考每段 65,536 个 UTF-16 代码单元，界面提供「继续加载」。工具参数和单个文件 diff 在点击后完整读取。

完成的工作块默认折叠。运行中的工作块沿用现有展开行为，加载步骤概况并实时更新，工具大段输出仍等点击才取。重要错误和未决提问、权限审批直接可见；做决定需要的命令、问题和改动内容不能因为懒加载而缺失。

详情在原展开位置显示紧凑加载状态，失败提供重试，不遮住正文。桌面点击、键盘和手机点击都可访问；hover 不是唯一入口。未知耗时、索引尚未就绪、确实没有详情分别表达，不显示假的 0 步或空内容。

## 数据读取模型

原始 `events` 仍是唯一真相。新增内容都是 Hub 数据库中的可重建投影，不修改 agent 文件，不覆盖或删除原事件。

`history.ts` 管理可重建读取模型：`history_rows` 保存轻量事件，`history_details` 保存原载荷引用，`history_turns` 缓存完成轮次的摘要，`history_coverage` 记录已构建区间。逻辑上分为三类：

1. **轮次正文与摘要**：以线程和轮次为键，保存有序正文块、工作块引用、状态、时间、计数、文件统计和起止 seq。一轮可以有多个工作块，保留计划、提问、审批造成的分隔。线程级另保存最新用量与未决交互，不依赖当前分页恰好含有其事件。
2. **工作条目索引**：保存条目位置、类型、标题、状态、预览、详情引用与版本。步骤列表读取不扫描工具载荷。标题和预览设长度上限，完整值留在详情，避免大命令混入摘要。
3. **详情索引与文本分段**：工具参数、输出、diff 可引用原事件中最后一次提供相应字段的 seq；字段按现有 `applyToolData` 语义分别更新，不能简单取最后一条事件。思考与中途文本按块聚合、分段。文件统计与详情引用独立存放，同一 diff 不因工具行和文件卡各复制一份。

新事件通过 SQLite savepoint 一起写入原日志、投影和构建区间，完成后才发布更新；savepoint 可以嵌套在批量导入事务中。旧数据按已构建区间继续处理，不使用不可回滚的内存摘要作为真相。

不在每个文字 token 到来时重写整轮大 JSON，不在常规请求时重新解析工具日志。文字增量保存在轻量事件表，思考只维护限长预览及原文范围；完成轮次首次读取时缓存摘要，后续事件使缓存失效。浏览器按 40 ms 短批次接收实时更新。

正文分组必须与现有 `buildTimeline` 等价：工具前的说明归入工作块，工具后的回答留在块外，保留计划和交互的顺序；末尾没有回答时沿用现有收尾规则。`partitionHistory` 是不依赖 React 和翻译的纯数据函数；测试将其投影交给现有 `buildTimeline`，与完整原事件回放比较，约束两侧分组规则保持一致。

## 接口

新增以下读取接口，不改变已有提交 turn 的接口。

| 请求 | 返回 |
| --- | --- |
| `GET /api/threads/:id/history?before=<cursor>` | 摘要 `events`、`nextCursor`、`hasOlder`、`snapshotSeq`；带入分页之前最近一次上下文用量 |
| `GET /api/threads/:id/history/work?turn=…&id=…` | 条目事件、`version`、`nextCursor`；继续读取附带 `cursor` 和 `version` |
| `GET /api/threads/:id/history/detail?turn=…&id=…` | 详情、`version`、`nextCursor`；继续读取附带 `cursor` 和 `version`；`path` 只筛选该工具已记录的 diff，不读取文件系统 |
| `GET /api/threads/:id/stream?view=summary&after=<seq>` | 正文增量、轻量状态更新、详情版本变化和显式续传水位，不推送未展开的重内容 |

详情标识由服务端产生并绑定线程、轮次与条目，不接受任意文件路径或跨线程 seq。沿用鉴权和多机代理。多页详情游标绑定版本，内容变化时明确要求重新获取该项，不能把不同版本的分段拼在一起。

`nextCursor` 表示历史分页边界，`snapshotSeq` 表示快照覆盖到的事件位置；两者不可再从返回数组的首尾推算。省略事件不代表它们尚未消费。没有可见更新时也要推进续传水位，避免重连反复扫描同一段日志。

新增摘要流独立于原始事件类型，不把裁剪内容伪装成完整 `StoredEvent`。现有完整事件读取、导出和内部订阅继续保留原语义。

## 实时一致性与前端接入

- 初始响应在同一读取快照内给出内容和水位 S，订阅从 S 之后接上；两次请求之间发生更新也不能漏。水位反映投影实际覆盖范围，不能直接拿数据库最大 seq 冒充。
- 断线以 `history.reset` 返回受影响轮次的轻量快照和水位，替换这些轮次，保留更早已翻到的历史；不退回完整工具事件。订阅在异步补齐前建立，期间只缓冲轻量事件，再发送快照水位之后的更新。
- 工具未展开时只更新标题、状态和详情版本。已展开的运行中详情最多每 250 ms 检查版本变化，当前请求完成后再刷新；同版本并发读取复用请求，过期响应不写入新的组件状态，折叠后停止刷新。
- 正文仍增量更新，不每个 token 重发整段回答。思考全文和工具输出不进入摘要流，运行进度用限长预览。待审批所需内容是明确例外。
- 抽出共用的历史分页、订阅、详情缓存和请求去重模块，供三个入口使用；不按 agent 名称分支，不需要新增 agent 能力开关。
- 缓存实例绑定当前 API 连接与线程，键含轮次、详情类型、标识和版本；连接或线程切换后释放，最多 100 项、约 8 MiB。切换线程取消请求或忽略过期响应，不能串到新线程。
- 详情进入独立缓存，不把旧事件追加到实时数组；重复展开复用缓存，获取旧详情不推进 SSE 游标，也不重建整段历史。
- 翻页和展开保留当前阅读位置，运行结束复用稳定块标识，避免正文闪烁、重复或跳动。侧聊用 `history?head=1` 只读取继承历史的水位，随后通过 `history?after=…` 直接读取新轮次，避免先加载再丢弃继承内容。

## 旧数据、迁移与边界

启动只创建读取模型的表和索引，不扫描所有历史。旧数据在请求对应区间时构建；每批最多 64 个事件，并按约 1 MiB／8 ms 提前让出事件循环，同范围并发构建复用任务。已建区间直接读取索引。

当前冷历史首个请求等待所需区间构建完成，再返回准确的正文、步骤数和文件统计；不会将重载荷发给浏览器。构建需要读取原事件，因此不能把冷历史首次请求当作摘要索引已就绪的性能。尚未采用「先返回不完整统计、后台补齐」的额外协议，避免出现假的零值或两套收尾规则。

冷历史首次重建仍有成本，单独测量；无法低成本还原的轮次显示局部加载状态，不能承诺与已建索引历史同样快。批次除事件数外还限制字节和时间，防止巨大载荷拖住服务。

导入与终端同步走同一规则。`copyEvents` 直接复制 SQL 记录，没有逐条调用 `appendEvent`，分叉后的新线程按缺失区间构建自身投影。删除线程级联清理投影与缓存；重启中断、取消、错误、无回答轮次和线程级分叉标记均需覆盖。

页面切换不为旧线程继续预取详情。完整导出仍读原日志，搜索继续使用现有索引。初次原生历史导入优化、完整诊断 trace 改造和全站虚拟列表不纳入本次。

1. 已完成投影、详情引用、旧数据按区间构建和语义对照测试。
2. 已增加摘要、工作条目和详情接口，保留原接口；测试鉴权、范围、游标、版本变化与事务回滚。
3. 已通过共用 `watchHistory`、`HistoryClient` 接入三个入口，支持摘要 SSE、按项缓存、分段加载、重试和历史翻页位置保持。
4. 默认入口已切换；完整导出、原始事件和内部订阅继续使用原日志。

验收要求：

- 固定同一份 8 轮重历史比较改造前后，另包含超长单轮、大量步骤、大 diff、纯文本和长正文。记录后端读取时间、gzip 前后字节、正文首次出现时间、JSON 解析与渲染开销、投影写入开销和磁盘增量。
- 分开记录冷历史、已建索引历史和详情首次打开。性能目标结合固定数据与环境实测确定，不预先宣称「秒开」或固定倍数。工具输出增大时，已建索引的摘要读取成本和传输体积不应同比增大。
- 网络：首屏不含工具参数、输出、思考全文和 diff 正文；展开工作块不请求全部工具详情；展开一个工具只取该项；重复展开命中缓存；刷新和重连不补传未展开详情。待审批所需载荷单独检查。
- 语义：问题、最终回答、计划、步骤顺序、耗时、文件统计、失败与取消、未决交互和完整导出保持正确；包含一轮多工作块、交错工具更新和缺字段快照。
- 一致性：快照与订阅间新增事件、断线期间多轮结束、详情返回时版本变化、快速切换机器或线程、分叉与删除、旧库中断后继续迁移。新增接口测试访问范围和分页边界。
- 统一层用各适配器的代表性事件验证；若引入适配器新行为，补对应假 agent。浏览器验证三个入口及桌面／手机、亮色／深色，检查点击、键盘、重试和滚动位置。
- 实现完成后运行 `npm run typecheck && npm test && npm run build`。固定样本的最近 8 轮：合并后的完整事件约 900 KB（gzip 6.3 KB），摘要约 6.4 KB（gzip 0.8 KB）；本机冷构建约 480 ms，索引就绪后的 HTTP 读取约 5 ms。重复文本容易压缩，这些数字仅描述该测试样本，不作为真实线程的速度承诺。桌面／手机、亮色／深色在真实无头 Chromium 中验证；实体手机未测。
