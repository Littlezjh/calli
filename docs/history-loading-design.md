# 历史正文优先与详情按需加载

状态：已实现。保持现有界面与统一事件模型，区分历史拉取和持续连接两条路径。

## 约定

- 已完成轮次：首屏返回提问、最终回答、结束状态、起止时间和工作概况。现有界面用起止时间计算总运行时间；导入记录没有可靠运行时间时仍不补造。
- 运行中轮次：首次打开只拉当前正文、状态、时间和步骤数。历史工作块保持折叠，点击后才加载已有过程；随后完整接收新发生的实时事件。
- 连续连接：完整推送正文、思考、工具参数、输出、文件变更、交互与结束事件，不以是否展开作为推送条件。已经收到的工具详情在本地展开。
- 刷新、重连：补齐历史概要，不重放断线期间的大段输出。保留当前页面已收到的完整工具事件；展开时仅在本地版本覆盖服务端版本时复用，缺失的新版本仍按需获取。
- 不调用模型生成摘要，不重写回答，也不修改 agent 的会话或配置。

## 历史首屏

`GET /api/threads/:id/history` 仍返回最近 8 轮，携带 `snapshotSeq`、`nextCursor` 与 `hasOlder`。正文和概况直接在服务端过滤，不依赖旧历史的缓存构建。

已有投影可用于读取小字段，包括已计算的文件统计。缺少投影时，查询原事件的类型、序号、时间等元信息，合并连续文字／思考区间，按既有时间线规则定位最终回答，再读取必要的正文和交互字段。工具参数、输出和思考全文不参与该路径，过程中的说明也不先读出来再丢弃。

首屏和重连不调用 `ensure`，不写入投影、覆盖区间或轮次缓存。旧记录、复制出来的分叉会话和中断的缓存构建都可直接读取。步骤数来自工具开始事件；待审批的决策内容直接返回，已解决的审批不携带工具正文。

旧记录中没有现成的准确文件增删统计时，不为了计算它而在首屏解析 diff，也不伪造零值。展开工作记录后，沿用已有文件统计与 diff 展示组件补充实际统计。已经有投影的记录仍直接显示这些统计。

首屏查询仍需要扫描所选轮次的事件元信息，最终回答本身很大时也仍需传输正文。因此不能承诺任意数据量下固定耗时；关键是工具输出的大小不再成为首屏读取与缓存补建的成本。

## 按需过程与详情

| 请求 | 内容 |
| --- | --- |
| `history?before=…` | 更早 8 轮的正文、状态和工作概况 |
| `history?head=1` | 仅取继承边界，供侧聊使用 |
| `history?after=…` | 仅取边界之后的新轮次 |
| `history/work?turn=…&id=…` | 工作条目、文件统计、版本与分页游标，每页 100 条 |
| `history/detail?turn=…&id=…` | 单个工具或思考的详情；文本每页 65,536 个 UTF-16 单元 |
| `history/detail?turn=…&id=…&path=…` | 单个已记录文件的 diff，不读取文件系统 |

已有的 `history_rows`、`history_details`、`history_coverage` 保留为可选的详情读取模型。新事件写入时维护；旧数据只在明确展开过程／详情后按需补齐，不成为首屏前置条件。批次按事件数、字节和时间让出事件循环，同区间并发构建复用任务。

详情仍按 API、线程、轮次、条目和版本隔离缓存，最多 100 项、约 8 MiB；重复展开复用结果。分页绑定版本，内容变化时重取，不拼接不同版本的内容。工具参数与单个 diff 暂不分段；这部分成本只发生在用户展开之后。

## 实时与重连

`stream?view=history&after=S` 先发送 `history.reset`，内容是 S 之后受影响轮次的轻量快照，随后发送完整的原始实时事件。旧的 `view=summary` 参数保留兼容，行为与此一致。原始事件读取、完整导出和内部订阅不变。

订阅先建立，再确定快照；快照期间到达的完整事件先缓冲，只发送水位之后的部分，避免丢失和重复。浏览器仍以 40 ms 短批次更新。

前端为历史工作块保留后续收到的完整事件。展开时把按需取得的过程条目与这些实时事件按序号合并，兼容工具开始于连接之前、结果产生于连接之后的情况。完整收到的新工具不再请求详情；没有收到的旧参数仍可通过详情接口取得。

历史拉取、实时事件、详情缓存与分页共用于主对话、协作成员和侧聊，不按 agent 名称分支。侧聊仍从继承边界之后开始读取。

## 验收

- 首屏无需投影：把旧工具／思考载荷替换为不可解析内容，正文、状态、时间与步骤数仍可返回；验证首屏和重连没有任何投影写入。
- 历史与实时分别验证：历史不包含工具参数／输出；同一个 SSE 连接的后续事件包含完整参数／输出。
- 语义对照：覆盖最终回答、工具后的收尾说明、多工作块、计划、交互、错误、取消、审批与上下文用量。
- 衔接：验证运行中首次打开、快照与订阅之间新增事件、重连、旧工具后续输出、新工具完整输出，以及过期本地数据不能覆盖服务端新版本。
- 浏览器：桌面／手机尺寸、亮色／深色；首屏不请求过程详情，历史点击后请求；持续连接中收到的详情本地展开。
- 完成后运行 `npm run typecheck && npm test && npm run build`。

固定 8 轮测试样本的首次读取：此前等待投影构建约 480 ms，本次直接过滤约 13 ms；摘要约 5.6 KB，完整合并事件约 900 KB。该样本数据高度重复，数字只描述测试环境，不代表生产速度承诺。

另以只读连接测量当前数据库中事件数最多的三条会话（约 15.9 万、11.4 万、9.6 万条事件），最近 8 轮的读取分别约 84、194、103 ms，响应约 30、26、93 KB。测试没有写入数据库；这些是服务端读取耗时，不包含网络传输和浏览器渲染。
