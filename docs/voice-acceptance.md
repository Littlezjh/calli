# 实时语音验收

本文用于实现接线后的人工验收。自动化测试使用假 agent 和合成音频，不能代替真实账号、麦克风、扬声器以及计费归属的核验。

## 环境和安装

1. 在运行目标线程的机器上确认 Codex CLI 可用，并使用现有 ChatGPT 登录。不要为本次验收增加 API Key 或切换到独立 API 计费。
2. 浏览器通过 HTTPS 或本机 localhost 访问 Hub。远端 HTTP 地址即使在 VPN 内，也不满足浏览器麦克风的安全上下文要求；桌面可使用 SSH 本地端口转发配合 localhost。
3. 打开扩展列表。缺少提供者或原生协议支持时应显示依赖问题并禁止安装；探测失败应与缺少依赖区分。
4. 安装实时语音扩展并确认语音权限。未安装或已停用时，输入框不应出现语音入口，也不应请求麦克风。
5. 在具备语音能力的线程中点击入口。登录或服务资格不满足时，应结束连接并显示错误，不得自动回退 API Key。

安装依赖满足不等于账号资格、实际音频和套餐计费已经通过验收。原生语音可能消耗现有用量；不得据此宣传免费或零用量。

## 听说与媒体生命周期

- 点击后才申请麦克风，确认能听到回应。状态须在原生握手和浏览器媒体均就绪后才显示已连接。
- 连续说两句话，检查字幕增量、最终文字和说话期间的播放；打断播报后可以继续交谈。
- 静音只关闭输入，任务继续执行；取消静音后可以继续说话。
- 结束语音后浏览器麦克风指示应消失。快速结束并重新开启时，旧请求不能覆盖新状态或关闭新麦克风。
- 权限弹窗尚未处理时结束语音，然后才允许权限；迟到的音轨也必须被关闭。
- 切线程、切机器、关闭页面、断网、停用或卸载扩展，检查媒体停止且没有自动重开。恢复网络或重新启用扩展后，必须再次点击才可开始。
- 第二个浏览器不能接管第一个浏览器的会话；同一目标已有语音时应明确提示占用。

桌面和手机均检查亮色、深色。真机另外检查耳机、扬声器回声、锁屏、切后台以及网络切换；无头浏览器的结果不能替代这些检查。

## 边聊边做

1. 先让语音助手执行一个范围明确的只读任务，例如读取项目说明并总结。
2. 后台任务运行时立即问另一个问题，确认对话没有被任务占住。
3. 检查普通线程出现真实的任务开始、执行内容和结束状态，而不是仅出现字幕。
4. 检查完成结果能回到同一语音会话，且播报与实际执行结果一致。打断播报追问时不能重复执行刚才的任务。
5. 运行较长任务后结束语音，确认任务继续存在并按原有规则执行；取消任务须走单独明确的操作。
6. 在原有审批模式下触发需要审批的操作，确认仍使用原有审批入口，语音连接不会提升权限或自动代答。拒绝或取消审批后，线程和语音都应恢复可继续操作的状态。

只验证到原生 `started`、SDP 或连接状态，不能将本节标记为通过。跨 agent 委托另行验收：必须记录目标机器与已有线程、唯一任务关联、真实执行状态、结果回传及取消边界。

## 验收记录

记录浏览器/设备、CLI 版本、登录类型、每项结果和失败的分类信息。不要记录 token、原始 SDP、音频、账号标识或个人路径。遇到上游不支持，应记录实际限制，不能用假 agent 测试结果覆盖它。

## 自动化覆盖（2026-10-19）

- `voice-production.test.ts`：真实子进程假 Codex、自主任务审批、任务在语音结束后继续、文字队列、会话交接、账号实例替换和不干净关闭后的隔离。
- `voice-http.test.ts`：安装门禁、登录与协议状态区分、owner 鉴权、私有 SSE、撤权和提供者变更。
- `voice-session-integration.test.ts`：旧请求迟到、错误保留、字幕增量/定稿/新句及内存上限。
- `voice-media.spec.mjs`：真实 Chromium 本地双 WebRTC peer，静音合成音轨，验证连接、播放、静音与释放。
- `voice-product.spec.mjs`：构建后的完整 UI、真实 daemon 与假 Codex，合成浏览器媒体；覆盖桌面/手机尺寸、亮暗主题、安装前隐藏入口、非语音提供方隐藏入口、静音/结束、审批保留，以及麦克风拒绝和停用后不自动重开。

以上不包含真实人物声音、真机回声、后台上游语音委托和账单核验。
