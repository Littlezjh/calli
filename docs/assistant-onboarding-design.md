# 助手下一步：一键配置、桌面宠物、吐槽把关

2026-11-06 · 规划稿（未开工）。接在 [个人数据落盘](personal-files-design.md) 和 [大肥鱼下一步](router-next-design.md) 后面。Playground 是临时页面，不进仓库。

## 为什么还用不起来

助手要先填好「私人设置」才会动：个人目录、agent、模型、「我的说明」（空模板）、飞书（开关、关注的人、关注的群、频率、会后跟进）、早晚报、主动行动，一共五块。关注的人和群要自己在飞书里一个个搜；「我的说明」要自己从零写。没配 agent 时，跟她说话只会得到「还没配置」。门槛在第一步。

用户的三条原则：

1. **按需拿数据。** 不订阅、不读模型的每条输出；有触发才读，读最少的那一层。
2. **少配。** 先让 AI 探索，再给人一份推荐清单，人点头就生效。
3. **助手可以吐槽。** 但吐完要说清哪里不对、下一句该怎么说，像一个 reviewer。

## 一、一键配置（P0）

### 流程

1. **入口。** 助手没配好时，她的第一句话就是「让我先看一眼你的飞书和 Calli 聊天，给你配一份？」加一个「一键配置」。私人设置顶部也有同一个入口（「重新探索」）。
2. **说清读什么。** 一张清单列出数据源、每项读多少，默认全开，可以逐项关。只读，不发消息。
3. **探索。** 逐行显示看到了什么（「王磊是你的上级」），约 30 秒。
4. **推荐清单。** 分组列出推荐，每项一句理由，依据点开才看。设置不全是开关，每种用合适的控件（见下面「设置的种类」）；推荐值已经替人选好，人只改不对的。
5. **按这样配。** 一次写入现有的各项设置，助手说一句「配好了：关注 N 人、M 个群……」。以后改设置就跟她说（已有 `calli settings`）。

### 读什么、读多少

先读元数据，必要时才读正文；原始内容不落盘，只留结论和依据。

| 数据源 | 命令 | 读多少 | 推出什么 |
|---|---|---|---|
| 你自己、你的上级 | `lark-cli contact +get-user`（自己，再按 `leader_user_id` 查一次） | 2 次 | 名字、部门、上级 → 关注的人（角色：上级） |
| 活跃会话 | `lark-cli im +chat-list --types=p2p,group --sort active_time` | 前 30 个，只要名字和活跃时间 | 常聊的人和群 |
| 你发过的消息 | `lark-cli im +messages-search`，发送人是自己，近 14 天 | 只统计跟谁、在哪、关键词；正文截断 | PM（谁常提需求）、在意的话题、活跃时段 |
| 日程 | `lark-cli calendar +agenda`，前后各 14 天 | 标题、重复规则、参会人数 | 固定会议、1:1 → 会后跟进、周报节奏 |
| 飞书任务 | `lark-cli task +get-my-tasks --complete=false` | 1 页 | 进「新发现」，人挑过才上桌 |
| Calli 对话 | 本地 store | 线程标题、目录、**你说的话**；不读 agent 输出和工具输出 | 常做的项目、你常纠正 agent 的点（写进「我的说明」） |

### 谁来判断

两段，代码收集、模型判断：

1. **收集器（代码）。** daemon 用 `execFile` 调 lark-cli、读本地 store，整理成一份事实包（每条带来源和计数）。只读、有时限、每源有上限；某源失败只标这一源，不影响其他源。事实包暂存个人目录 `.calli/explore.json`（0600），应用后删除。
2. **一次判断（模型）。** 用 `ThreadManager.askOnce` 开后台一次性线程（始终归档，不碰任何 agent 的会话），把事实包交给助手的 agent，要求输出推荐 JSON：每项带理由、依据、置信度。模型需要补看时只能用一个受限命令（如 `calli explore read chat ID --limit 20`），每次探索最多补看几次。
3. **校验。** 推荐里的人和群 ID 必须出自事实包，否则丢弃；角色只取 `boss | pm | other`；「我的说明」草稿过一遍 `personalText` 拒绝凭据。

### 推荐清单里有什么

| 组 | 推荐 | 写到哪 |
|---|---|---|
| 助手 | agent 与模型：有额度的 agent 里选轻量模型 | 私人设置 agent / model |
| 关于你 | 「我的说明」草稿 | `profile.md`（只在仍是模板时直接写；已写过的给差异，人选） |
| 关注的人 | 上级、PM、常合作的人，带角色 | 飞书 people |
| 关注的群 | 常 @你 的群 | 飞书 chats |
| 会后跟进 | 固定会议和 1:1 | 飞书会议事件 |
| 节奏 | 早晚报时间、安静时段，按你的活跃时段推 | brief、盘点安静时段 |
| 待办 | 未完成的飞书任务 | `inbox`（新发现） |
| 助手的脾气 | 吐槽强度、主动行动「先观察」 | 新设置 `companion.roast`、`proactive.mode` |

### 设置的种类

参考 iPhone 专注模式的「允许的联系人」：系统先按往来预填几个人，人可以去掉、用「+」加别人；Superhuman 的 VIP 名单单独管理，搜索添加、逐个移除。名单类设置照这个做，不拆成一排开关。

| 种类 | 例子 | 控件 |
|---|---|---|
| 开关 | 推到飞书 | 开关 |
| 几选一 | 用哪个 agent、多久看一次飞书、不打扰时段、吐槽强度、主动做事 | 选项短且不超过 3 个用分段控件，否则用 `Popover` 列表，每项可带理由，推荐项标「推荐」 |
| 名单 | 关注的人（带角色）、关注的群、会后跟进的会、放进「新发现」的飞书任务 | 推荐的已选好，其余是候选，按往来排序；多的收进「还有 N 个」；能搜索添加不在候选里的；人带角色（上级 / PM / 其他） |
| 开关加时间 | 早晚报 | 开关，打开后显示早报、晚报两个时间 |
| 草稿 | 我的说明 | 默认收起，展开是可直接改的纯文本 |

名单有两种摆法，playground 里可切换：

- **就地改（推荐）：** 名单是一排小块，已选的实线，候选的虚线带「+」，点一下加进来；点已选的弹出依据、角色和「不关注了」。
- **点进去改：** 清单一行一项只写结论（「王磊、陈思 等 4 人」「2 个群」），点进去是完整列表：搜索框、「推荐（已选）」与「其他候选」两段、每人一行带理由和角色。

### 前提不满足时

- 没装或没登录 lark-cli：清单照出，只用 Calli 的数据；飞书一组显示「登录飞书后能多看 5 类」和登录入口，不报错。
- 没配 agent：探索前自动选一个能用的 agent（有额度、支持一次性提问），清单第一项就是它。
- 探索中断：已看到的结果留着，「继续」从断点接着看。

### 之后

不再弹表单。助手每周最多提一次变化：「你最近常跟 X 聊，要加进关注吗？」一条建议，一个按钮。

## 二、桌面宠物（P1）

现在她只在网页的「桌面」页。三种走出来的办法，越往后越像真桌宠，也越要多装东西：

| 形态 | 好处 | 代价 |
|---|---|---|
| A. 网页里所有页面都在，可收起成小圆头像 | 立刻能做，手机也一样 | 网页关了她就不在 |
| B. 浏览器画中画小窗（Document PiP） | 不用装，置顶在所有应用上 | 只有电脑上的 Chrome / Edge；有边框；浏览器不许自己弹出，要人点一下 |
| C. 桌面小 App（Tauri，`packages/desktop-pet`） | 透明、置顶、开机自启、可穿透点击，真桌宠 | 要装；macOS 透明窗口需要私有 API 开关；手机仍是 A |

C 只是一个壳：加载 hub 的 `/pet` 页面（只有助手和气泡），连接方式沿用现有的地址加 token，不另写一套界面。建议先做 A，再按 playground 的选择做 B 或 C。

出现方式三档，三种形态通用：

- **常驻**：一直在角落。
- **有事才出来**（默认）：平时收起；她回复了、有事等你确认、要吐槽时才出来，说完约 10 秒退回去。
- **关**：不出来、不吐槽，只在「桌面」页能找到她。

她不能挡住输入框和发送按钮；在线程页收到边上。

### 说话方式

现在她说话用带边框和阴影的大卡片，按钮排在下面，要手动关，太重。改成两种轻的形式，按内容分工（playground 里四种可切换对比）：

- **状态条（学 Codex）。** 平时只有她，状态靠她的动作表达。鼠标移到她身上（键盘聚焦、手机点一下）时，脚下才出现一条细胶囊：状态点、线程名 · 状态（在跑 / 等你 / 好了 / 卡住），最多一个主动作（「去看」），右边是「写一句」和「线程」两个图标。新状态到达时露约 4 秒再藏回去；有事等你时，她身上留一个小点（隐藏的是细节，不是「有事」）。点胶囊展开全文；点「线程」出一个小列表，等你的排最前。手机上第一次点她出状态条，再点才是跟她说话；点别处收起。
- **小气泡（学 `/buddy`）。** 头顶一句短话（约 15 字），带小尾巴；动作就是气泡里的一两个词；8 秒后开始变淡、11 秒消失。点气泡看全文。
- **分工：** 线程状态进状态条；吐槽和提问用小气泡。分析结果和配置清单不是「说话」，仍用输入框上方的一条或对话框。
- 宠物默认改小（约 60 像素宽，和 Codex 差不多），能拖到任何位置，位置记住。

## 三、吐槽与把关（P1）

### 什么时候出来

只看**人发出去的话**，用本地规则判断，不调模型、不读模型输出：

- 命中生气用语：笨、蠢、又错、还是不对、说了几遍、什么鬼、wtf、连续的「！！」「？？」等。
- 同一线程连续三次纠正，或中断后马上重发。
- 已经在手边的状态：这一轮失败了，或跑了很久没有改动（现有统计，不额外读取）。
- 人点她「帮我看看」。

冷却：说完一句后同一线程 5 分钟内不再主动开口；每小时最多 3 次。出现方式为「关」时完全不触发。

### 出来后做什么

1. **先吐槽一句。** 这一句由模板加已有的元数据生成（轮数、工具名单、是否跑过测试），不调模型。
2. **点了才分析。** 读最近两轮：人的话、agent 的最终回答、工具名单和次数；不读工具输出全文、不读更早的对话。用助手的 agent 开后台一次性线程，输出：最多三条「哪里不对」（每条指向具体的话或工具记录）、一句建议的说法。
3. **人决定。** 「填进输入框」只把建议放进输入框，人自己发；不往 agent 的会话里写任何东西。卡片底部写明读了什么、没读什么。

### 吐槽强度

关 / 温和（默认）/ 毒舌。只改语气，不改触发条件和读取范围。毒舌也不骂人，只调侃 agent。

### 方向（playground 里选）

- A. 发出去后吐槽一句，点了才分析（推荐）。
- B. 发出去前拦一下：输入框上方冒一行「先别骂，要我看看？」，点了才分析并给替换句，不点照样能发。
- C. 只吐槽，不分析。

## 分期

1. **第一期：一键配置 + 全局助手。** 收集器、`POST /api/personal/explore`（返回探索 ID）与进度事件、推荐 JSON 校验、推荐清单与应用；助手出现在所有页面，加「出现方式」设置。测试：扩展 `test/fixtures/fake-lark-channel.mjs` 支持通讯录、会话列表、日程；假 agent 对探索提示返回固定推荐 JSON。
2. **第二期：吐槽与把关。** 本地触发规则（web 端，带测试表）、冷却、`POST /api/threads/:id/review`（只取最近两轮与工具名单）、复核卡片、填进输入框；`companion.roast` 设置可经 `calli settings` 改。
3. **第三期：桌面形态。** 按选择做画中画小窗或 Tauri 壳；`/pet` 精简页面。
