# 写作流程设计

状态：设计稿第一版，未实现。更新：2026-10-24。

给线程开一个写作流程：人口述观点，agent 采访、记录、补充，按初稿、二稿、三稿、配图、润色几个阶段把一篇文章写出来。它不是编辑器，是一套写作流程：正文是一个 Markdown 文件，人可以当纯文本直接写（键盘或输入法的语音输入），也可以选中一段标注，让 agent 去改。

出发点：观点要是人自己想出来的，哪怕偏激。AI 适合在输入端加料（采访、查资料、跨领域的比喻、挑刺），不适合在输出端替人下结论；润色尤其容易把尖锐的观点磨圆。流程的每一步都按这个分工来。

## 核心决定

- **流程属于 hub，不属于某个 agent。** 阶段存在 hub，换 agent 时跟着走，没有写作能力的 agent 也能用。
- **不安装技能。** 每个阶段的做法写成一小段说明，由 hub 附在用户消息后（`<calli-writing>`，界面不显示），和目标、进度报告同一个做法。
- **只开一个小口子：正文可以直接改。** 线程目录下 `writing/` 里的 `.md` 文件可以在文件面板里当纯文本编辑；其他文件仍然只读。不做富文本，不做语音（用输入法自己的语音输入）。
- **两种改法并存。** 自己写得出来的直接写；想让 agent 动手的，选中一段加注释。
- **人写的和 AI 补的分开。** AI 补进正文的内容带标记，人确认「留」以后才去掉标记。
- **提醒不是关卡。** 阶段由人推进；agent 可以建议「可以进入下一稿了」，不自己推进。大师们的提醒人可以不接受，agent 记下，不再重复。

## 用户入口

1. 输入框左下角的加号菜单「写作模式」，和计划模式、目标模式放在一起，点一下就开始，不弹对话框。
2. 不先建文件、不先填题目。agent 在第一轮按内容起题目，把正文写到线程目录的 `writing/<题目>.md`。线程目录是 git 仓库时不排除这个目录：文章是产出，不是 hub 的工作文件。
3. 输入框上方一条阶段状态：`初稿 · 二稿 · 三稿 · 配图 · 润色`，当前阶段高亮，旁边是正文文件的链接（点开就是文件面板）。点下一个阶段推进，也可以退回。点「结束」退出写作模式，正文文件保留。
4. 手机上状态条收成一个阶段名，点开是阶段列表。

## 阶段

每个阶段附在消息后的说明不同。下面是说明的意思，措辞实现时再定。

| 阶段 | 人做什么 | agent 做什么 | 提醒 |
|---|---|---|---|
| 初稿（关门） | 口述，一段一段说 | 只采访、只记录：用人的原话写进正文，不加自己的观点和材料；人说不清、要查的地方标 `【待补：…】`；每轮最多问一两个问题，问具体场景（「那是哪天、写到哪一句」），不反驳 | Lamott：一只鸟一只鸟地写，一英寸画框；Paul Graham：像说话一样写 |
| 二稿（开门） | 在正文上标注：待补、为什么、举个例子、删、留，或写一句评论 | 补 `【待补】` 和注释要的内容，查到的资料写明出处；补进正文的内容加 `〔补〕` 标记；人标「留」的去掉标记 | Pinker：知识的诅咒，读者不知道你知道的 |
| 三稿（删） | 决定删什么 | 指出可删的字句段和理由，人同意才删；报告这一稿比上一稿短了多少 | King：第二稿 = 第一稿 − 10%；鲁迅：可有可无的删去；Orwell；Zinsser 的「杂物」 |
| 配图 | 选图 | 提出哪里需要图、画什么，画好放进 `writing/<题目>/` | Pinker：图是带读者去看，不是装饰 |
| 润色 | 逐条接受或拒绝 | 只改语言；改动列成清单，**改变了意思、磨掉了棱角的单独列出**，人确认才改 | Paul Graham：念一遍，别扭的就改 |

默认只采访和补充，不反驳。要讲事实、做实验的文章，人在对话里说一声（「这篇帮我挑刺」），agent 再质疑事实和论证、找反例和已有工作。不设文章类型选项：分两类太武断，分多了又成了表单。

## 写作习惯

改文章时，有些意见只针对这一句，有些是人写东西的习惯（「不对读者说教，不用『你』指读者，用『自己』『人』」）。后者沉淀在 `~/.calli/notes/writing.md`：人自己的笔记，不属于哪个项目，换目录、换 agent 都跟着走；普通 Markdown，从任何线程都能打开、直接编辑，不放进某家 agent 自己的 Memory。`~/.calli/notes/` 统一放这类沉淀（以后可以有 `code.md` 等），`CALLI_NOTES_DIR` 可以改位置。线程的 `writing` 里带 `habits`（这份文件的绝对路径），界面据此给出入口。

- 每个阶段的说明都要求 agent 动笔前先读它。
- 人说「复盘」「总结一下」时，agent 回看这次对话里的注释、人直接改过的地方、被否掉的写法，提炼成习惯追加进去，每条新记的标〔新〕，回复里逐条列出请人确认；确认的去掉〔新〕，不要的删掉。只针对一句的改动不记，和已有习惯冲突时先问。
- 不做成 Skill：Skill 要装进每家 agent，格式各不相同；放在写作说明里所有 agent 都能用。
- 有的 agent 默认只能写自己的工作目录（例如 Codex 的沙箱），往 `~/.calli/notes/` 写可能要审批。

## 直接编辑正文

- 文件面板打开正文文件时，顶栏多一个「编辑」。点了以后预览换成整页文本框，内容就是 Markdown 原文。桌面在右栏里编辑，手机全屏，系统键盘和输入法的语音输入都能直接用。看起来像写字的纸，不像代码编辑器：正文字体、舒服的行高和宽度，没有行号、高亮和工具栏。
- 保存：「保存」按钮，桌面另有 Ctrl/Cmd+S。没保存的内容按线程存在本机（和输入框草稿同一个做法），刷新、切走再回来都还在。退出编辑前有没保存的内容要确认。
- 和 agent 撞车：读文件时 daemon 给出内容的哈希，保存时带上。文件在这期间被 agent 改过，daemon 返回 409，界面提示「正文被改过」，你写的内容留在文本框里，可以复制，再选择载入新版本或覆盖。agent 正在跑的时候也能编辑，只是保存更可能撞上。
- 让 agent 知道：人保存过正文以后，下一条消息附的写作说明里加一句「正文在上一轮之后被人直接改过，先重读再动手，不要改回去」。
- 接口：`PUT /api/threads/:id/writing/text?path=`，只认线程目录 `writing/` 下的 `.md`（解析符号链接后再判断），带 `baseHash`；大小沿用文本读取的 1 MB 上限；写入用临时文件加改名，不留半截文件。

## 文件面板里的注释

现在选中文字加注释只能在对话里用（`SelectionMenu` 只认 `.thread` 里的选区）。扩到文件面板：

- 预览和源码两种视图都能选中。注释进入输入框时，原文之外多一行文件位置，agent 按原文在文件里定位，不依赖行号：

  ```text
  [注释 1]
  文件：writing/思考是人类的事情.md
  > 选中的原文
  评论：删
  ```

- 写作模式下，选中菜单多一排快捷标签：`删`、`待补`、`为什么`、`举个例子`、`留`、`改成…`（点了展开输入框）。不在写作模式时只有普通注释。
- 「文件：」和「评论：」一样是给 agent 解析的协议文字，不翻译。
- 注释本身不改文件，是发给 agent 的消息。agent 改完，文件面板按现有方式刷新。

这一块不依赖写作模式，普通线程看代码时也能用。

## 接口约定

前后端按这一节对接。

- 阶段：`WritingStage = 'draft' | 'second' | 'third' | 'figures' | 'polish'`（初稿、二稿、三稿、配图、润色）。
- 线程上多一个字段 `writing: { stage: WritingStage; file: string | null } | null`，不在写作模式时为 `null`。`file` 是正文相对线程目录的路径（如 `writing/思考是人类的事情.md`）：每轮结束时 daemon 取 `writing/` 下最近修改的 `.md`，还没有就是 `null`。
- `PUT /api/threads/:id/writing`，body `{ "stage": WritingStage }`：开启写作模式或切换阶段，返回线程。`DELETE /api/threads/:id/writing`：结束，返回线程。两者都发 `thread.updated`。轮次进行中也可以改，从下一条消息起生效。
- `GET /api/threads/:id/text?path=` 的返回多两个字段：`hash`（整个文件内容的 SHA-256 十六进制；二进制或被截断时为 `null`）和 `editable`（路径在线程目录的 `writing/` 下、以 `.md` 结尾、不是二进制、没被截断时为 `true`）。
- `PUT /api/threads/:id/writing/text?path=`，body `{ "text": string, "baseHash": string }`：保存正文。成功 `200 { "hash" }`；磁盘上的内容和 `baseHash` 对不上时 `409 { "error", "hash" }`（`hash` 是磁盘上现在的）；路径不可编辑 `403`；文件不存在 `404`；超过 1 MB `413`。
- 正文里的相对路径图片，前端走现有的线程图片接口按 `writing/` 下的路径取，不新增接口。

## 不做

- 富文本编辑器、正文以外文件的编辑、多人实时协作。
- 语音输入：用手机或电脑输入法自带的。
- 自动推进阶段、给文章打分。
- 发布到博客或其他平台。成稿就是那个 Markdown 文件，怎么发由人决定。

## 实现范围

- daemon：线程上的写作状态（阶段），存储加列；开启、推进、结束的接口；`writing.ts` 按阶段生成说明，在 `threads.ts` 里和进度说明同一处附加，斜杠命令不附加。保存正文的接口（只认 `writing/` 下的 `.md`、哈希不符返回 409、超限拒绝、原子写入），保存后下一轮说明里提示重读。测试覆盖每个阶段的说明、斜杠命令不附加、结束后不再附加、越权路径（含符号链接）和过期哈希被拒。
- web：加号菜单入口、阶段状态条（桌面和手机）、正文的编辑与保存（本机草稿、撞车提示）、文件面板的选中注释和快捷标签、三种语言的文案。
- 假 agent 不用改：说明是普通文本，测试检查发出去的消息里有没有它。
- E2E：开启写作模式、推进阶段、编辑并保存正文、agent 改过后保存被拒、在文件面板预览里选中加注释、手机布局。

## 待定

- 一个线程只写一篇，还是可以写多篇。第一版一篇，写完结束再开下一篇。
- 每一稿要不要留快照（`writing/<题目>/v1.md`），方便对比。线程目录是 git 仓库时可以直接看 git 历史；不是的话第一版不留。
- 配图放在正文旁边的文件夹，还是统一放 `writing/<题目>/`。
