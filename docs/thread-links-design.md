# 会话深度链接

## 目标与取舍

以稳定的 Calli 会话 ID 串通“复制链接 → 搜索定位 → 其他模型查阅”，复用已经存在的鉴权页面与只读引用，不新增公开分享服务或系统 URI 协议。

参考 Codex App 的会话深链入口，以及 [LibreChat 路由](https://github.com/danny-avila/LibreChat/blob/main/client/src/routes/index.tsx) 将认证会话 `c/:conversationId?` 与公开分享 `share/:shareId` 分开的做法。Codex 的 `codex://threads/<id>` 来自[公开观察资料](https://joshpadnick.com/twig/guides/codex-sessions/)，未核验 App 实际 handler；不据此推断其访问权限。

## 技术方案

### 身份与地址

地址为当前 Calli 部署的 HTTP(S) URL 加 `#/thread/<Calli Thread.id>`；远端机器追加 `?machine=<machine id>`。无机器参数表示主 Hub 本机，不能解释为“当前选中的机器”。保留部署子路径，复制时去除原查询参数、凭据和旧 hash，不携带 token。

Calli 会话 ID 与 agent 的原生 session ID 分开。未导入的原生会话没有可复制的 Calli 深链，不启动或导入原生会话来造链接。原有 `thread://` Markdown 内部链接及短 ID 定位保持不变。

侧栏右键、更多菜单和手机长按共用“复制深度链接”；会话页放在已有“复制”子菜单内。目标机器取菜单所用 scoped API，不取当前显示机器。复用 Clipboard API 与 HTTP/iOS 降级；两种复制均失败时弹出可选中完整地址的对话框，避免手机展开列表遮住会话页错误提示。

### 精确搜索

搜索框中的完整深链或 hash 走独立身份查询，以对应机器的 `Api.thread(id)` 返回单个会话结果，不把 URL 送进全文搜索、不伪造轮次命中。结果不依赖侧栏分组，因此空会话、归档会话、协作子会话与交接链指定段都可定位。

查询不切换机器、不恢复归档，也不授予 agent 读取权限；用户点击才沿用既有深链打开流程与归档恢复。无效或其他部署链接、未知机器、离线、认证失败及查询失败分别提示。响应须与查询和连接作用域匹配，避免旧响应覆盖后续输入。普通标题、目录和全文搜索不变，不新增“链接＋关键词”语法。

### 跨模型只读引用

在明确的用户发送边界提取正文里的会话深链，保留原链接和文字，将同机目标通过 `createReference({kind:'thread', sourceId})` 转为已有会话引用。重复链接与已附加来源去重，沿用最多 12 个引用的限制。

正文候选增加有限容错：只在明确的 `#/thread/` ID 段识别完整 UUID；紧接的中日韩文字、破折号和省略号作为正文边界，末尾冒号可作为标点。识别用副本移除常见零宽字符、软连字符和 BOM，将排版连字符及 UUID 大小写规范化；仅解码一次，只有完整 UUID 才采用修正结果。常见空白、引号、Markdown 包裹与重复链接继续支持。普通旧 ID、有歧义的 ASCII 后缀、截短 ID 和非法路径不猜测；裸 UUID 不自动成为引用。

容错不改输入框、原链接、草稿或发送正文，不在粘贴/输入阶段创建引用；保留原部署地址、子路径及完整机器查询参数，再执行已有严格校验。机器名紧接正文无法无歧义区分时仍明确报错，不删参数回退成本机。搜索/导航的 `parseThreadLink()` 精确契约不变，不接受新增的“链接＋关键词”语法，也不扫描、导入或模糊查找不存在的会话。

智能引号只按原文中的成对外包装处理，不作为查询值内部的无条件分隔符，避免把非空 machine 变成本机。BOM 可修复 UUID 内的复制噪声，但实际作为空白分隔符时必须继续扫描后续链接，不能只保留首段。中文后缀含路径、查询、片段或控制字符等有歧义结构时不截短为 UUID，也不忽略紧贴的其他 URI；须在任何快照创建前完整校验或明确拒绝。

已创建的引用写回对应草稿；发送失败、重试、排队、撤回排队、刷新和编辑沿用已有引用协议及相同快照。无效来源或跨机器引用在发送前报错，不部分发送；异步解析不能写入已切换的草稿。终端活动确认保存发起时的发送闭包，用户切换会话或机器后确认仍发往原接收会话与 scoped API。SSE 与 HTTP 回执只扣除当次已发送内容，保留之后新加的附件；SSE 已确认后，延迟 HTTP 回执不再次清除新输入，即使新文字与上一条相同，HTTP 响应丢失也不把旧引用放回草稿。

编辑会重写接收会话历史，导致该会话自己的快照失效。因此编辑正文中的自链接，以及已保留的同会话整段引用，都在创建引用和提交编辑前拒绝，并提示先移除自链接与引用；不会先改写历史再报错。普通追加消息仍可引用当前会话的固定快照，单条消息快照不受这项整段历史限制。

后台授权逻辑不变：仅接受发送/排队时授予接收线程，模型使用已有 `calli references ID` 分页读取正文、长回复和工具详情。链接不是凭据，模型输出链接、纯搜索和导航不会自动授予读取权限。读取不会运行或修改来源、不会切换工作目录，也不扩大个人助手或交接历史权限。

快照固定在附加时的历史范围。来源继续输出不自动纳入，来源删除或历史重写明确报错。本功能中的“跟踪”指定位和查阅，不是持续监听。

不同模型、agent 和账号实例可查阅同机附加来源；跨机器深链支持复制、打开和搜索，跨机器完整会话引用暂不支持并明确提示。单条跨机器消息仍沿用原有消息快照，不能冒充完整会话。其他独立 Hub 或任意外部 URL 不被抓取。

- `components/Sidebar.tsx`、`App.tsx`：独立精确查询、机器校验及点击打开。
- `context-references.ts`、`components/Composer.tsx`、`ThreadView.tsx`：发送/编辑时解析引用，复用快照、草稿与引用序列化；SSE 与 HTTP 回执共用已发送内容扣除逻辑，保留点击发送后新加的附件，SSE 已确认的消息不因 HTTP 响应丢失重新附加引用；编辑预先拒绝正文自链接和已保留的自会话整段快照，其他输入入口提供自身 scoped API。`App.tsx` 的终端发送确认绑定发起时闭包，不使用确认时新选会话的发送函数。
- `i18n/locales/{zh,en,ja}.ts`：三语言菜单与错误状态。
- 前端单测和浏览器回归：链接格式、身份定位、菜单、引用授权及失败恢复。
