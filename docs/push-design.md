# 推送：首版用 Lark CLI

2026-10-25 · 设计稿，实现中。属于 [个人 agent](personal-agent-design.md) 的「找得到你」，也是 TODO 第 5 节系统通知、第 6 节外部提醒的第一个出口。

需要你时，手机上收到一条飞书消息，点开回到对应线程；不需要你时不发。Web Push 要先上 HTTPS，飞书客户端手机上本来就有，所以先用 [Lark CLI](https://github.com/larksuite/cli)（`lark-cli`）以机器人身份私聊你。

## 推什么

只推需要你的事，对应个人 agent 设计里三档提醒的前两档：

| 情况 | 默认 | 说明 |
|---|---|---|
| 等你批准、等你回答、计划待确认 | 开 | 线程进入等待时推一次 |
| 一轮失败 | 开 | 不含你主动停止、重启中断；协作成员的失败交给主控，不推 |
| agent 主动通知（`limi notify`） | 开 | 见下文 |
| 定时任务跑完 | 关 | 可在设置里打开 |
| 普通一轮完成 | 不推 | 仍然走未读 |

不推：导入的历史、终端同步、控制轮（`/goal`）。判断复用 `lifecycle.ts` 的 `turnOutcome`、`turnOrigin`、`attentionOf`，不另写一套。

只覆盖 hub 本机的线程。其他机器上的线程以后和多机器提醒一起设计。

## 推送内容

```
[Limi] 等你批准 · 整理报销单据
pi · 10:42
打开：<线程链接>
```

- 只带种类、线程标题、agent 名和时间。不带审批详情、命令、消息正文和回答，这些可能含敏感内容，发到飞书就是发到外部服务。
- `limi notify` 的文字是 agent 写给你的，原样带上，最多 500 字符，标明「来自 agent」。
- 链接：设置里填了「Limi 地址」才带，例如 VPN 下手机能打开的地址；没填就不带。链接格式 `<地址>/#/thread/<线程 ID>`，不带 token。

## 去重、限流、失败

- 同一线程的同一次等待只推一次；等待解除后再次进入，算新的一次。
- `limi notify`：同一线程每分钟最多一条，多的丢弃并记日志。
- 全局每小时最多 30 条，超出的丢弃并记日志，设置页显示丢弃数。
- 每条超时 15 秒，失败重试 2 次（间隔递增）。队列在内存里，daemon 重启时丢掉未发出的，不补发历史。
- 每条带幂等键（线程 ID + 事件序号），重试不会重复发送。

## 怎么调用 Lark CLI

```
lark-cli im +messages-send --as bot --user-id <你的 open_id> --markdown - --idempotency-key <键>
```

- 用参数数组启动，不经过 shell；正文从标准输入传入。
- 子进程环境去掉 hub 的 token 和 `LIMI_*` 凭证（同个人浏览器的做法）。
- 可执行文件：`LIMI_LARK_CLI` 指定，否则在 PATH 里找。找不到、机器人身份未就绪时，设置页如实显示，不推送。
- 飞书的凭证由 Lark CLI 自己管理，Limi 不读、不存。

## 设置

「配置 → 推送」一页，存在 hub 的 SQLite（`hub_settings`），不写入仓库：

- 开关，默认关。
- 状态：Lark CLI 是否找到、机器人身份是否就绪（读 `lark-cli auth status`）。
- 接收人：默认取 `lark-cli auth status` 里已登录用户的 open_id，可以改。
- Limi 地址：用于生成链接，可空。
- 各类开关：见「推什么」。
- 「发一条测试」按钮。
- 最近 20 条推送记录：时间、种类、线程、结果（已发、失败及原因、丢弃）。只留在内存里。

## 线程深链

网页支持 `#/thread/<线程 ID>`：打开时进入这个线程，然后把地址换回普通样子（同计划页的 `replaceState` 做法）。线程不存在时停在原处，提示找不到。未连接 hub 时先走现有的连接流程，连上后再打开。这也补上 TODO 第 6 节的「线程深链」。

## `limi notify`

```
limi notify --text-file FILE    # FILE 可以是 -
```

- 走现有的能力 socket 和本线程的凭证（`LIMI_TOOLS_KEY`），只能通知自己所在的线程。
- 在线程里记一条 `agent.notice` 事件，时间线显示为一行简短提示；线程标未读；推送开着就推。
- 文字为空或超过 500 字符时报错。

## 接口

- `GET / PUT /api/push/settings`
- `GET /api/push/status`：Lark CLI 与身份状态、最近记录、丢弃数。
- `POST /api/push/test`

## 不做

- 从飞书回复、在飞书里直接批准（以后做入站时再设计）。
- 群聊推送、多接收人。
- 其他机器上的线程。
- 「页面正开着这个线程就不推」：以后再加。

## 验收

- 单元与接口测试用一个假 `lark-cli` 脚本记录参数和标准输入，覆盖：各种触发与不触发、去重、限流、超时重试、幂等键、找不到 CLI、身份未就绪、环境变量不泄漏、`limi notify` 的权限和长度。
- 真实发送一次测试消息到本人飞书，手机上点链接能回到线程。
- 设置页和深链在桌面、手机，亮色、深色下看过。
