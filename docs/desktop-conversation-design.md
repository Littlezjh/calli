# 会话旁查看桌面与 Computer use

状态：按推荐 A 方案实现了第一步，按用户要求整合到主分支；独立 Computer use 画面与人工接管仍为后续计划。目标是边聊天边看 agent 操作，参考用户提供的左会话、右桌面截图。

## 支持范围与部署前提

- 当前被查看、操作的远端桌面只支持 Linux；观看端仍可使用手机或电脑浏览器。
- 部署时会在 Linux 主机上安装并启动 VNC 服务端，提供可连接的图形桌面。Calli 通过现有代理与前端 noVNC 展示该桌面，安装和启动属于环境准备，不由打开会话面板触发。
- Agent 操作的有界面浏览器必须位于对应的 VNC 桌面，用户才能看到同一画面；独立无头 Computer use 仍按第二步另接任务画面。

## 当前基础

- `DesktopPanel.tsx` 已接入 noVNC，支持观看、键鼠、剪贴板、手机触控、最小化和重连；`App.tsx` 目前把它作为覆盖会话的窗口打开。
- `desktop.ts` 已提供机器桌面探测、短期连接票据与多机代理，可以复用。
- `calli/browser` 操作有界面的个人浏览器，Chrome 显示在 VNC 桌面上；旁边打开对应机器桌面即可观看，但画面是机器共享桌面，不是会话独占环境。
- `codex/computer.use` 操作 `BrowserComputer` 创建的独立无头 Chromium。每步截图交给执行 agent，当前不会显示在机器桌面，也没有面向用户的连续画面接口。不能因为打开了 VNC 就宣称能看到这类任务。
- 当前「控制」只是切换 noVNC 输入权限，没有暂停 agent、控制权互斥或自动恢复协议。

## 建议交互

1. 会话顶栏提供「桌面」入口，有可用桌面时显示；现有侧栏与命令入口保留。宽屏点击后在右侧打开，聊天和输入框始终可用。
2. 初始比例以会话约 45%、画面约 55% 作为原型起点。支持拖动分隔线和展开画面；空间不足时切换为独立画面页，不挤出两个不可用的窄栏。最终尺寸在 playground 验证。
3. 与文件、工作记录等辅助面板共用位置；同一时刻只显示一个。打开时保持聊天阅读位置、草稿和输入框稳定。
4. 从会话入口打开时，电脑和手机都默认观看；不会自动抢键盘焦点。手机在「会话 / 桌面」间切换，回聊天保留草稿和滚动位置，等待审批和错误仍有可见提示。现有独立桌面入口的操作模式与新观看入口分别定义，避免无意改变手机运维习惯。
5. 顶部只保留机器名或任务名、连接状态及必要动作。机器桌面明确标示共享范围，不能标为当前会话独占。切换机器时关闭旧连接，切换同机线程时不暗示画面随线程隔离。
6. 打开后才加载观看代码与画面；关闭释放观看连接，最小化沿用现有保持连接语义。二者都不停止 agent 或浏览器。独立任务画面隐藏后停止订阅，重新打开只取最新画面。
7. 初次加载保持画面容器尺寸；重连保留最后一帧并标记断线，不能把旧图显示为实时。连接失败、不可用、尚未产生画面分别显示。

## 实施顺序

### 第一步：会话与现有桌面并排

- 按 UI playground 流程先做两个可操作方向：A 为右侧可调宽桌面（推荐），B 为更大的桌面配紧凑会话栏；均提供手机与亮暗主题。选择后再实现正式组件。
- 从 `DesktopPanel` 中分离必要的窗口外壳与观看区域，保留一份连接状态。并排、展开、收起切换不能因重新挂载而反复握手。
- 在 `App.tsx` 接入辅助面板位置与会话入口，处理现有面板互斥、跨机器切换和键盘焦点。继续按能力与机器可用性判断，不按 agent 名字分支。
- 复用现有桌面 API 和代理，首步不新增后端接口。界面文字补齐中、英、日三语，视觉使用现有变量与图标。
- 验收产出：使用 `calli/browser` 操作页面时，用户能在旁边看到真实过程，并继续发消息。

### 第二步：独立 Computer use 任务也可观看

- 建立调用线程、委托任务、执行环境的明确关联，返回实际可观看能力。多个任务时由用户选择，不根据工具名称或目录猜画面归属。
- 首先复用每步已经产生的截图，新增受鉴权保护的最新帧读取与轻量更新通知；只保留有界的最新帧缓存，订阅时传输，不把图片塞进历史正文或向所有 SSE 客户端广播。
- 将该模式明确标为「步骤画面」，标示更新时间；它能看操作结果，但不承诺连续视频。任务结束保留经过校验的最终截图，取消、失败和过期有明确状态，释放临时资源。
- 如果验收需要连贯的鼠标和页面动画，再独立验证 Chromium 画面流方案；保持同一执行环境，避免为展示偷偷改成共享个人浏览器。是否采用连续流以延迟、带宽和代理兼容性实测决定。
- 新接口覆盖线程与任务授权、多机路由、断线恢复、过期及并发隔离；适配器新增行为同步补假 agent。

### 后续独立能力：人工接管

首版以观看为验收核心，保留现有手动控制能力，但不得标注「agent 已暂停」或「独占控制权」。要做到截图里的「获取控制权 / 交还」，需要执行端能确认暂停、等待在途动作结束、互斥放行输入，并处理断线后的归属。受 Calli 管理的执行环境可逐项接入；直接运行的外部工具无法可靠暂停时，不承诺自动交接。

## 验收清单

- 在已安装并启动 VNC 的 Linux 主机上验证完整连接链路；没有可用 VNC 时不得显示为已连接桌面。
- 宽屏并排时能聊天、观看和拖动分隔线；展开再返回不丢草稿、不跳阅读位置、不重复建连接。
- 观看时聊天输入、快捷键、滚轮不会泄漏到远端；切换焦点和控制模式后行为明确。
- 手机竖屏、横屏及亮暗主题都在真实浏览器验证；实体手机未测时明确记录。
- 检查首次加载、密码输入、失败、断线重连、最小化、关闭、跨机器切换全过程。
- 用 `calli/browser` 走一次可见的真实页面操作；第二步另用独立任务证明画面确实来自该任务，两个并发任务不串图。
- 新增或调整相关桌面 E2E 与任务接口测试；实施后运行 `npm run typecheck && npm test && npm run build`。
