# 配置页面与菜单

本轮按已选 Playground 的 B（电脑分类与详情并排、手机逐页进入）和柔和玻璃实现。短菜单沿用所选的锚定浮层方向。Playground 仍是临时验证材料，正式代码不依赖它。

## 参考与取舍

- 用户提供的 Codex 手机截图：配置分组列表、单一页面标题；返回与工具按钮分别使用玻璃材质。截图里的设置本身也有 sheet，因此目标不是禁止所有浮层，而是避免“大容器、整条导航胶囊、按钮”连续套三层。
- [Chatwoot 的配置路由](https://github.com/chatwoot/chatwoot/blob/develop/app/javascript/dashboard/routes/dashboard/settings/settings.routes.js)：配置作为可以定位、返回的页面，适合内容多的设置。
- [Open WebUI 的设置容器](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/SettingsModal.svelte)：按类别组织内容可借鉴；多项配置放在同一个 modal 的承载方式不沿用。
- [LibreChat 的 DropdownPopup](https://github.com/LibreChat-AI/LibreChat/blob/main/packages/client/src/components/DropdownPopup.tsx)：短操作保留在触发位置附近，与完整配置页区分。

## 行为

「配置」占满窗口，隐藏会话侧栏及其拖动分隔线。电脑只保留配置分类与详情，手机先显示分组入口，再进入单个详情；左上角返回逐层回退，离开配置后恢复原会话和侧栏偏好。配置页不响应展开会话侧栏的快捷键或边缘滑动。常规、外观、语言、推送、私人设置、自动交接和机器使用统一页面容器；智能体、团队、技能、MCP、扩展及统计页也从同一导航进入。旧独立页面地址继续可用。归档、历史导入、额度查看和删除确认沿用各自的临时操作界面。

私人设置先显示目录、智能体和模型，飞书、简报、主动行动、个人资料点击后分别加载和编辑。每个子页只保存本页数据。推送完整记录、机器候选和定时任务运行记录按需读取，加载失败可重试。

统一入口不代表所有子流程已经迁移。额度、归档、历史导入、技能与 MCP 的详情和安装、外部扩展配置等仍使用弹窗。2026-11-06 按实际组件重新核对的范围、后续优先级和额度参考方案见 [额度与配置遗留审查](quota-navigation-review.md)。

定时任务采用同一列表／详情关系。电脑并排查看，手机进入任务后显示单独编辑页。名称和提示词在前，执行配置在后；保存操作固定在底部。

未保存的配置在应用内返回、切换类别、浏览器历史导航时先提示；取消保留编辑状态，保存失败也保留输入。保存中阻止跳走。进入设置前的会话草稿和阅读位置在返回后恢复。刷新页面重新读取已保存配置，不承诺恢复未保存的配置表单。

## 材质与菜单

正文和配置页保持不透明。玻璃只用于返回按钮、会话工具组、输入框、短菜单和固定操作栏。手机顶部不再放一整条带边框的圆角玻璃容器，不重复显示大标题。颜色、边缘高光、阴影和模糊量使用 `styles.css` 顶部变量；不支持背景模糊或系统要求降低透明度时退回实色。这是网页对玻璃材质的近似，不是原生 iOS 的完整折射效果。

菜单与值选择器共用材质、间距和触摸尺寸；手机也锚定触发位置，长列表内部滚动。支持键盘选择、Escape、视口边界约束，保留长按后防误触。手机子菜单在同一浮层内切换，桌面在旁边展开。

## 验收

`settings-navigation.spec.mjs` 覆盖电脑／手机尺寸、浅色／深色、配置页入口、锚定菜单、保存失败重试、草稿离开确认、浏览器返回、详情按需加载和返回会话。原有常规、外观、私人设置、定时任务、技能与 MCP 等浏览器测试同步到新导航。

浏览器验证使用 Chromium；真实 iPhone Safari 的键盘、滚动及玻璃观感仍需真机验收。

本轮检查结果：初始化冒烟、全仓库类型检查、单元测试与构建通过（单元测试 1514 通过、1 跳过）。配置导航、保存失败、草稿返回、触摸菜单、定时任务布局、分组筛选、常规、外观、飞书、技能与 MCP 的相关浏览器用例通过。扩展回归中仍有自动交接的 3 条用例、远程交接草稿的 1 条用例失败；没有据此宣称全量 E2E 通过，也没有扩展修改交接实现。
