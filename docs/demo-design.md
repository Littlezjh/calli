# 先看界面，再连接

状态：第一版已实现。更新：2026-10-16。

现在打开页面先看到一张输入 token 的卡片（`TokenGate`），没有 token 什么都看不到。第一次来的人不知道这是什么，也没法先试一下。改成：没有 token 也直接进主界面，看的是一套内置的示例数据；要真正用的时候再连接。

## 核心决定

- **没有 token 就进示例。** 示例是整套真实界面，数据是写死在前端里的，不请求 daemon 的任何接口（`/api/health` 也不请求）。没有 token 的人从 hub 拿不到任何东西，和现在一样。
- **示例在前端换一个 `Api`，界面不分两套。** 新加 `DemoApi extends Api`（`src/demo/`），读接口返回示例数据，写接口统一抛 `DemoError`（`write: true`）。`App` 拿到的还是一个 `Api`，组件不用判断「是不是示例」。只有少数入口（顶部提示条、配置菜单、终端）看 `api.demo`。
- **一动就请连接。** 能看、能点开、能切换；凡是要 daemon 去做的事（发消息、新建线程、审批、改名、删除……）都弹出「连接」对话框。草稿保留，连接后还在输入框里。
- **已经有 token 的人看不到示例。** 打开时 localStorage 里有 token，就和现在一样直接进真实数据，不闪示例。
- **连接前先验证 token。** 现在是先存再用，错了才被踢回来。新的对话框先拿 token 请求一次，成功才保存、切到真实数据；失败就在对话框里说原因，对话框不关。

## 打开后看到什么

和已连接时同一套版式，多两样东西：

1. **顶部提示条**（桌面在主区顶栏下方，手机在列表页和对话页顶部，各一条，不重复）：

   `示例数据，不会发给任何 agent。` ······ `[连接 hub]`

   一行，背景用 `--surface-2` 一类的浅底，不用警告色。按钮是主操作样式。手机上文字缩成「示例数据」。
2. **配置菜单** 第一项是「连接 hub」，不显示「退出」。「外观」照常可用（纯本地），「已归档」是空的。「机器」「技能」「用量与诊断」「导入历史」「额度」「添加 agent」第一版在示例里不显示，见文末「不做的事」。终端按钮和斜杠面板里的终端、技能、额度、导入也改成弹出连接对话框。

输入框照常可以打字。按发送时弹「连接」对话框，不清空草稿。输入框的占位文字改成「连接 hub 后就能发消息」。

## 示例数据

一个虚构的项目 `~/projects/demo-app`，几个线程，覆盖最能体现好看的几种画面：

| 线程 | agent | 画面 |
|---|---|---|
| 给登录页加深色模式 | Codex | 完成的一轮：Markdown 回复、代码块、改动卡片（diff）、工具调用折叠块 |
| 修复列表滚动跳动 | Claude | 停在审批卡片上，等用户批准一条命令 |
| 迁移到新的路由写法 | pi | 计划模式：计划卡片和提问表单 |
| 周报整理 | Codex | 归在另一个分区里，显示分区效果 |

另外：

- 计划看板有三四张卡片，分在不同列，其中一张连着上面的线程。
- 定时任务有一条（每天早上），显示下次运行时间。
- agent 列表给三个可用的 agent，`capabilities` 写全，这样模型、权限、速度这些选择器都能打开看。
- 线程状态写死，不模拟流式输出。「运行中」这种动态效果第一版不做（见待定）。

数据放在 `packages/web/src/demo/`，事件用和真实 daemon 一样的 `StoredEvent` 形状，走同一套 `buildTimeline`。不写真实的路径、主机名、人名。

示例数据只在没有 token 时用动态 `import()` 加载，已连接的人不多下载这部分。

## 连接对话框

用 `DialogSurface`，标题「连接到 hub」。手机上和别的对话框一样从底部弹出。

```text
┌──────────────────────────────────────┐
│ 连接到 hub                            │
│ 连接后再发送，输入框里的内容会留着。 ← 有原因时 │
│ 输入 hub 的访问 token，只保存在这台设备上。 │
│                                      │
│ [ RAH_TOKEN                   ]       │
│ token 是 hub 所在机器上 .env 里的        │
│ RAH_TOKEN。    ← 失败时换成红字的原因     │
│                                      │
│                    [取消]  [连接]      │
└──────────────────────────────────────┘
```

- 「连接」按下后变成转圈，期间不能再点。用 `api.agents()` 验证：200 成功；401 显示「token 不对，请检查后重试」；网络错误显示「连不上 hub，请检查地址和网络」。
- 成功：`saveToken`，`setToken`，`App` 换成真实 `Api`，示例数据全部丢掉，停在空白的新线程页（示例线程在真实数据里不存在）。新线程的草稿保留。
- 从「发消息」打开时，标题下面多一行「连接后再发送，输入框里的内容会留着。」

## token 失效和退出

- 已连接时 token 失效（任何接口返回 401）：现在是清 token、回到输入卡片。改成清 token、回到示例，并直接打开连接对话框，里面显示「token 无效或已过期，请重新输入」。
- 主动「退出」：确认对话框的说明改成「这台设备上保存的 token 会被清除，回到示例数据。」退出后回到示例，不弹对话框。

## 实现要点

- `api.ts`：`send` 和直接用 `fetch` 的几个方法（上传视频、读文件、附件、`stream`）都在 `DemoApi` 里覆盖。只覆盖 `send` 不够。`stream` 在示例里一直挂着，直到 `signal` 中止，不报错，不重连。
- `DemoApi.send` 按「方法 + 路径」查表：查到就返回副本；查不到的 `GET` 抛 `DemoError`（`write: false`），由调用方原有的错误处理接住，界面上什么也不说；非 `GET` 一律抛 `DemoError`（`write: true`）。唯一例外是打开线程时的「标为已读」，在示例里本地改掉。以后新加读接口，示例里最差是空，不会坏。
- `handleError` 认 `DemoError`：写操作打开连接对话框，读不到的不提示。
- token 从 `App` 提到 `main.tsx` 的 `Root`。连接、退出、失效都换一个 `key` 重新挂载 `App`，示例的状态一点不留。`api` 总是有值：有 token 是 `Api`，没有是 `DemoApi`。`TokenGate.tsx` 删除，样式里 `.gate` 一段一起删。
- `useHosts`：没有 token 时本来就不请求。示例里 `hostId` 恒为 `null`。
- `SkillsPage` 自己 `new Api(token, …)`，示例里不显示技能页，所以不用改；以后要在示例里显示，改成从 `App` 传进去。

## 测试

- 单元：`DemoApi` 的读接口返回示例数据，写接口抛 `DemoError`，`stream` 在中止前不返回。
- e2e（`packages/e2e/`）：
  1. 不带 token 打开：看到侧边栏的示例线程、提示条，点开一个线程能看到改动卡片。期间没有任何 `/api/` 请求。
  2. 在示例里按发送：弹出连接对话框，草稿还在。
  3. 输错 token：对话框里显示错误，没有保存到 localStorage。
  4. 输对 token：进入真实数据，提示条消失。
  5. 已连接时让 token 失效：回到示例，对话框打开并显示原因。
- 截图：桌面和手机、亮色和深色，各看一遍示例主界面和连接对话框。

## 不做的事

- 示例里不跑真的 agent，也不模拟一个「假 agent 会回话」。体验到的是界面，不是 agent。
- 示例里不显示「机器」「技能」「用量与诊断」「导入历史」：这几个页面的示例数据要单独编，第一版先不做。
- 不做用户名密码登录，仍然是一个 token。

## 待定

1. **带 token 的链接。** 例如 `/#token=…`，打开就自动连接，然后立刻从地址栏抹掉。手机上第一次连接很方便（电脑上点「复制连接链接」，手机扫码）。代价是 token 会进剪贴板、聊天记录或截图。倾向第二版再做，并且只在已连接的设备上生成。
2. **示例里的动态效果。** 让一个线程「运行中」，计时器在走，消息一段一段出来，第一眼更有感觉。代价是要写一个按时间回放事件的假流。倾向先不做，看静态示例够不够。
3. **公开部署一个只有示例的页面。** 和 hub 无关的静态站点，放在 README 里给人点开看。示例做完后几乎是顺带的，要不要做另说。
