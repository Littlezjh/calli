# 实时语音接入设计

状态：首版代码与生产接线已落地，默认未安装；等待真人听说与原生「边聊边做」验收。跨 agent 为第二阶段实验能力。

当前实现包含 `ext-voice` 安装门禁、宿主媒体控制、HTTP/SSE、独立语音租约、Codex 生产会话接线、原生自主任务与审批、浏览器入口及中英日文案。自动化已覆盖假 agent 的完整任务循环及真实 Chromium 页面；不把这些结果当作真人声音、上游实际委托或套餐计费已经通过验证。

## 目标与约束

在手机和电脑浏览器中连续语音交流，同时查看当前线程的任务、审批和结果。优先使用 Codex 原生实时语音及现有登录，后续把任务转交给已有的 Pi、Claude Code 等线程。

- 不引入独立 GPT-Live API 账单，不配置新的 API Key，不自动回退到按量付费 API。
- 不承诺零用量：原生语音及可能的 Codex 调度会消耗现有额度，目标 agent 仍按自己的方式计费。
- 不直接修改 agent 的目录、全局配置或历史文件；通过原生协议管理会话。
- agent 协议差异留在 `packages/daemon/src/adapters/`，前端依据能力和实际连接状态展示。
- 不把「协议存在」「账号可用」「音频可通」「额度归属已确认」混为一谈。

### 核心体验：持续聊天、后台委托、语音回报

用户明确要求以「边聊边做」作为最终验收目标：说出任务后，语音助手把工作交给后台执行模型或 agent，用户继续与语音助手交谈，后台结果再回到同一个语音会话中汇报。

- 语音会话与后台任务分别管理状态和生命周期。委托的启动只等待接收结果，不等待整个任务结束；后台繁忙不能占住语音对话。
- 区分普通交谈与明确的执行请求，不把每句字幕都作为新 prompt 提交。一个明确任务对应唯一任务关联，重复字幕或重连不能导致重复执行。
- 后台真实的排队、执行、待审批、失败和结束状态回传给语音层。先播报简短结果，用户追问时再取必要详情；不能仅凭工具调用已返回就声称任务成功。
- 用户可以继续说话或打断播报。停止播报、结束语音与取消后台任务是独立动作；语音关闭后任务仍按原有规则运行，重新开启也不能自动重复派发。
- 「停一下」「改一下」等指代不明的指令先确认所指任务。审批沿用现有授权，不将普通聊天或一句无明确目标的「好」解释为批准操作。
- 首先在同一个 Codex 线程验证完整循环，再验证同机 Pi / Claude Code 的受限转交。跨 agent 的完整体验仍以原生委托或协调会话实测为准，不承诺仅凭 WebRTC 连接成功就已经具备。

验收场景：用户说「帮我跑测试」，后台开始工作；用户立即问另一个问题，语音仍能回应；测试结束后语音报告真实结果；用户打断播报追问失败原因；同一测试任务全程只运行一次。结束语音后在普通线程中仍可看到该任务的真实状态。

## 已知证据与待验证项

本机 Codex 0.160.1 导出的实验协议提供 `thread/realtime/start`、`stop`、`listVoices`、`appendText`、`appendSpeech`，以及字幕、音频、错误和关闭通知。WebRTC 启动参数含 SDP offer；启动响应为空，SDP answer 通过 `thread/realtime/sdp` 异步返回。接口存在不等于服务端授权成功。

`clientManagedHandoffs` 的描述仅涉及 Codex 响应回传，不能据此推定客户端能够替换后台执行 agent。不同实时协议版本的行为需要单独验证，不将所有版本字段组合后盲目重试。

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 支持生成与已安装版本一致的 schema，并说明实验接口需在 initialize 中声明 `experimentalApi`。

[官方套餐价格说明](https://learn.chatgpt.com/docs/pricing?codex-pricing-plans=individual) 当前明确说明 Desktop Voice 消耗现有 Codex budget，语音与任务共享用量限制。该说明不能直接证明第三方 Hub 的 app-server 语音具备相同账号资格和计费归属。实施前以当前账号、原生错误和用量记录核验；不通过时保留原有文字功能，不自动更换登录方式。

## 架构

### 可选扩展与安装依赖

`packages/ext-voice` 已注册为默认未安装的可选内置扩展，沿用 board / memory 的安装、启停和授权流程。未安装时不展示语音入口、不请求麦克风、不建立连接。扩展入口包独立分块；媒体控制器属于宿主基础代码，定义随页面加载，但构造不访问麦克风或创建连接。媒体、原生协议和凭据始终由宿主管理。

安装依赖为「当前机器有可用的原生语音提供者」，首个提供者为已实现 `realtimeVoice` 与只读 `realtimeSupport()` 的 Codex 适配器。清单声明所需能力，宿主查询适配器，不让前端按 `agent === 'codex'` 判断。

- 没有 Codex / CLI 不可用 / 原生协议不支持：扩展目录显示缺少依赖，禁止安装；服务端也校验，不能只禁用按钮。
- CLI 和协议存在但未登录 / 账号资格未验证：单独展示认证与服务状态，不把安装依赖已满足当成语音已可用。开始会话时检查现有 ChatGPT 登录，禁止 API Key 回退。
- 安装、启用和每次开始语音都重新核对依赖。运行期间提供者退出、被移除或扩展被停用，由宿主清理连接与授权；保留安装记录，便于恢复后重试。
- 安装范围是机器，不是当前线程的 agent。首版只支持同机 Codex 原生线程；未来 Pi / Claude Code 线程选择同机 Codex 作为语音提供者。仅浏览器设备安装 Codex 不算满足远端机器依赖。

当前外部扩展只允许工作数据源权限和 Node ESM 进程，不能加载任意浏览器代码。首版不拓宽第三方包执行范围，也不把语音伪装成 `commands.run` 工作数据源。

### 需要增加或落地的扩展接口

下表区分首版实现和后续预留；预留接口不代表扩展现在能调用它。

| 接口 / hook | 当前代码状态 | 本次最小职责 |
| --- | --- | --- |
| `manifest.requires.agentCapabilities` 与依赖状态 | 已接入只读协议/登录探测、能力快照及安装/启用强校验 | 声明原生语音依赖；宿主在安装、启用、运行时核验，返回满足、缺失、未知、失败及原因 |
| `contributes.composerActions` | 已实现声明、校验及宿主输入框插槽 | 输入框注册语音动作，宿主统一图标、排序和手机布局；不改写发送动作 |
| `WebHost.realtime` | 仅预留可选只读类型，首版未向扩展实例注入 | 首版通过声明式动作请求宿主控制器；不开放第三方直接 start、原始 SDP、RPC 或 token |
| 会话级状态 / 字幕订阅 | 已实现专用 VoiceEvent SSE 与 owner 校验 | 按已绑定线程与 owner 投递状态、临时字幕、最终项；与普通元数据通知分流，读不到其他线程的内容 |
| `agent.changed` | 类型已预留，未实现 | 提供者变更后刷新依赖并终止失效会话；缺少该通知时，开始时仍必须重新校验 |
| `extension.deactivating` / dispose | 已通过 `extension-voice.ts` 接入生产 runtime，onChange 直接撤销租约 | 停用、卸载、撤权、崩溃时由宿主收回租约并停止媒体；不能依赖扩展收到尽力投递通知后主动清理 |
| `turns.transcript` | planned | 第二阶段按目标线程授权读取有限近期正文；不用 `threads.list` 泄露正文或通过元数据权限读取 |
| 有时限的语音输入会话授权 | 尚无接口 | 第二阶段连续语音委托的范围、次数/去重和失效检查；绑定 extension/provider/host/thread/owner/generation，停用或结束立即失效 |

复用已有 `turn.started`、`turn.finished`、`attention.raised`、`attention.resolved`、`host.resync` 和扩展存储，不另造审批 hook。语音状态与正文读取分别授权；已接入 `voice.control`、内置扩展运行时检查和宿主浏览器控制接口。跨 agent 另需目标线程的 `task.control` / `transcript.read`。浏览器麦克风许可不能代替 Hub 的线程授权。

现有 `threads.send` 契约只允许一次用户点击绑定的 `clickToken`，不能把一次点击包装成无限发送。持续语音是用户显式开启的输入会话，需要独立的限时授权；也不能借 `driver.next` 绕过排队和任务控制。该扩展不获得代人批准、任意命令或写 agent 配置的权限。

扩展默认不能注册模型工具或改 prompt。若 P2 最终需要动态工具，工具由宿主以固定实现挂到专用语音协调会话，扩展仅请求已绑定目标的受控动作；需在扩展设计中明确这一宿主能力的边界，不开放第三方自定义 prompt 或任意工具注册。

### 宿主与扩展职责

扩展负责语音入口、设置和交互呈现。宿主负责鉴权、安装依赖、麦克风与连接生命周期、租约、真实任务状态与原生审批；Codex 适配器负责协议差异。不开放 `beforePrompt`、发送拦截或审批自动答复。

```text
浏览器（麦克风、播放、字幕）
  ├─ WebRTC 音频 ←→ Codex 原生语音服务
  └─ HTTP / SSE 控制 ←→ Hub 语音协调层
                            ├─ Codex 原生语音适配器 ←→ app-server
                            └─ 目标线程 ←→ 现有 agent 适配器
```

### 浏览器

用户点击入口后才申请麦克风并建立连接；浏览器控制器构造本身不访问媒体。默认仅显示按钮；连接期间展示紧凑状态、最新字幕、静音和结束按钮。音色等辅助设置按需展开，失败、权限拒绝和待审批信息直接可见。

使用真实音频轨道和 WebRTC 播放。连接成功须以媒体连接状态为依据，不能把 start RPC 成功显示为音频已连接。浏览器端和服务端都要有启动超时、连接代次标识及清理机制。

### Hub 语音协调层

区分语音提供者与执行任务的目标 agent。会话绑定 `host / agent instance / thread / owner / generation`；每线程同一时刻一个语音 owner，首版切换线程或机器即结束旧语音。迟到回调不能写入新会话。

负责开始、停止、心跳租约、临时信令、字幕与任务关联、幂等转交、断线清理。SDP、原始音频和凭据不进入普通事件日志或调试输出。控制接口沿用 Hub 鉴权和目标机器代理。

静音只关闭音频输入；结束语音主动关闭原生实时会话和浏览器媒体；停止工作另走明确的任务操作。不能用现有 `cancelTurn()` 实现结束语音，因为其可能停止协作并清除排队消息。

#### HTTP 控制契约

所有接口沿用 Hub Bearer 鉴权；跨机器请求经现有 host proxy 转发，目标 daemon 的绑定 `hostId` 固定为 local，不信任请求正文指定的机器或提供者。除提供者列表外，额外要求浏览器宿主在每个页面实例内生成随机 `X-RAH-Voice-Owner`，只保留内存，不给扩展读取、不放入 URL 或正文。它限制同一 Hub 账号下不同浏览器误控会话，不能代替 Hub 认证。

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/voice/providers` | 返回已探测提供者的 id、available、supported 和分类原因；不返回原生报错或账号信息 |
| `POST /api/voice` | `{extensionId:'voice', threadId, offer}`，返回 201 和状态快照；提供者由目标线程决定 |
| `GET /api/voice/:id/events` | 专用 SSE，默认 data 帧包含状态、SDP 或字幕；不持久化、不回放字幕、禁止缓存 |
| `POST /api/voice/:id/heartbeat` | 续期并复验权限；建议每 10 秒发送，租约默认 30 秒 |
| `POST /api/voice/:id/connected` | 浏览器确认媒体连通；仍须等原生 ACK 和 started 才显示 connected |
| `DELETE /api/voice/:id` | 幂等结束，仅回收语音资源，204 |

慢速 SSE 消费者受缓冲上限约束；订阅断开立即结束当前语音租约。前端不得自动重新打开麦克风，需要用户再次点击。停用/卸载、提供者失效和 daemon 退出均由宿主主动回收连接。提供者只读探测合并并缓存 30 秒，实例替换或移除会使缓存失效；开始语音时原生控制器仍独立验证 ChatGPT 登录。

### Codex 原生适配器

复用现有 app-server 与线程。实时事件监听必须在发起启动请求前建立，处理异步 SDP、字幕、错误和关闭。对于原生自主发起的 turn，绑定实际 turn ID，确保审批、工具记录、状态与结束事件完整。

适配器已新增持久的 `SessionHooks`，接收原生自主 turn 生命周期；普通 `prompt()` 的 hooks 清空后，会话级接收仍有效。不能仅挂音频接口而遗漏后台审批，也不能把语音字幕再次提交 `prompt()` 导致重复执行。

### 跨 agent 转交（实验）

首先核验原生协议是否允许客户端接管任务委托。如果不支持，再验证一个由 Hub 明确管理的 Codex 语音协调会话，通过受限动态工具转交目标线程。该会话的存在、生命周期和用量需要可见；不能假装其为目标 agent 的原生语音能力。

现有 `limi send` 只访问本次协作成员，`spawn` 会创建新线程，不能直接拿来转交用户任意已有会话。需要新增只授权已绑定目标的转交接口，不向语音会话暴露 Hub 全局 token。首个跨 agent 实验限定同机，跨机控制在同机链路通过后验证。

目标线程沿用自己的模型、权限、计划模式和审批，不继承协调成员的默认权限。当前统一接口没有通用 steer 能力；执行中追加默认排队，只有适配器明确支持时才允许原生追加。用户打断播报不取消任务，不将“已排队”播报成“正在执行”。

## 网络

浏览器麦克风需要安全上下文，参见 [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

- 电脑验证：SSH 本地端口转发，浏览器访问本机 localhost。
- 手机与日常使用：受信任 HTTPS 入口反向代理到现有 HTTP daemon；仍可仅在 VPN 内开放。证书须被设备信任，VPN 不代替安全上下文。
- WebRTC 音频通常由浏览器直达上游，须单独验证浏览器网络；Hub 信令经 SSH 可达不等于音频可达。
- HTTPS 入口同时代理页面与 API，避免页面调用远程 HTTP API 的混合内容问题；SSE 不应被代理缓冲。

## 历史与上下文

只持久化必要的最终字幕、任务关联、执行结果及会话结果。临时字幕与最终项按原生 item/session ID 合并，重新连接不得重复写入。音频默认不落盘。

上下文按当前目标按需构建：最近对话、当前任务和必要结果。详细工具输出在需要时才读取。跨线程重新绑定时不得继承其他目标的语音上下文。对外播报以真实任务状态为依据。

- [ ] 验证真人音频输入输出、字幕、打断和关闭；静音连接探测不能代替听说验收。

新接口须有鉴权、超时、幂等、旧版本不支持和错误状态测试；适配器新增行为在假 agent 中对应实现。真实上游和假 agent 的验证结果分开记录。

浏览器覆盖桌面与手机尺寸、亮色与深色；手机真机检查权限、扬声器回声、耳机、切后台、断网与音频恢复。无头浏览器不能替代真机听说验收。

提交前运行 `npm run typecheck && npm test && npm run build`。需要重启 Hub 时只使用 `scripts/restart.sh`；测试子进程只清理自己记录的 PID。

### 复现命令

只读探测不会创建线程或开始语音：

```bash
node scripts/codex-voice-probe.mjs
```

真实原生连接探测会创建临时只读线程，并可能消耗现有套餐用量。WebRTC 模式需要已安装的 Chromium；使用静音合成轨道，不读取真人麦克风，不播放或保存音频：

```bash
node scripts/codex-voice-probe.mjs --connect --protocol v3 --audio-output --webrtc
```

脚本明确区分 RPC 接受、started 通知、SDP 和 peer connection 状态；不把这些信号当作音频或订阅计费已验收。

### 生产接线补充（2026-10-19）

- `VoiceService` 已接入 daemon 启动、HTTP 服务和关闭流程；独立语音 SSE 断开、停用扩展、提供者移除/替换都会撤销媒体租约。只读协议探测确认 CLI 提供 realtime 接口；是否允许账号连接仍在每次原生 start 时验证，不把安装成功当作账号授权或计费保证。
- `ThreadManager.voiceTransport()` 在占用租约后延迟建立/复用当前线程会话，取消初始化中的语音不会迟到启动媒体。`CodexSession` 将 realtime 通知交给独立控制器，把原生自主 turn 交给会话级 hooks；普通 turn 结束不会清空会话级 hooks。自主任务沿用任务事件、审批和文字队列；字幕不会重新作为 prompt 发送，也不会存入任务事件表。
- 原生关闭确认后，可在同一线程打开下一段语音；未确认关闭、直接释放的通知源不能安全重用，明确拒绝再次启动，不擅自创建新任务线程或迁移上下文。关闭语音不调用 `turn/interrupt`，任务仍可等待审批、继续输出及完成。
- 新增 `voice-production.test.ts`，覆盖只读探测、语音自主任务审批、结束语音后继续任务、文字队列只派发一次、普通任务中打开语音、正常/异常关闭后的重开边界、API Key 拒绝及启动中取消。生产接线第一轮 daemon 回归：599 项，598 通过、1 跳过、0 失败；后续改动仍需最终全仓验证。
- 跨 Pi/Claude 等提供者的显式任务绑定、结果注入与语音委托身份尚未实现。本阶段只接当前原生提供者的线程，不把其他 agent 会话自动变成语音目标。真实麦克风听说、原生委托是否持续双向回复及实际额度计入方式仍按人工验收清单验证。
