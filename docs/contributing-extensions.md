# 一起扩展 Calli

Calli 希望用简单的界面管理更多国内外 agent，让每个人都能把好用的工具和工作方式带进来。可以先反馈一个真实问题，也可以贡献文档、适配器或插件。无需先做一个完整的平台。

本文介绍当前 master 已有的入口；接口仍在迭代，设计文档中列出的候选 hook 不等于已经可调用。

## 先用现有插件

在「配置 → 扩展」中安装、确认权限，然后打开或配置。插件按机器管理；不使用时可以停用或卸载。

### Board

**线程看板**随项目提供，按需安装。它把当前机器的线程分为进行中、等你、待验收、已完成，列由线程状态和 agent 每轮结束的进度报告推出；点击卡片回到会话，手机使用页签。agent 只能请你验收，完成由你勾选。

源码：[ext-board](../packages/ext-board)。这是一个内置视图插件，通过公开的 `WebHost` 接口使用线程摘要、导航和宿主组件。

### Memory

**Memory 记忆看板**随项目提供，授予只读权限后安装。当前支持读取 Codex 实例已有的记忆文档，提供分类、标题与摘要搜索、预览和原文。没有已有记忆或读取失败时会显示相应状态。

它不生成记忆，也不让没有原生记忆能力的 agent 自动获得记忆，不同步不同 agent 的记忆。源码：[ext-memory](../packages/ext-memory)。

### LoopX

**LoopX**是可安装的独立工作数据源。先自行安装、初始化 LoopX，再从扩展目录安装插件，检测版本、配置 registry，显式关联目标和线程。会话摘要与看板可以展示同一份目标、待办和待决定事项；看板读取关联目标需要单独授权。

当前接入展示状态，不自动发消息、暂停任务或推进下一轮。已验证的 LoopX 版本与运行环境见 [安装说明](../packages/ext-loopx/README.md)，协议与验证范围见 [接入记录](loopx-integration.md)。

## 选择一种参与方式

| 想做什么 | 从哪里开始 |
| --- | --- |
| 提一个需求、反馈手机体验 | [提交 issue](https://github.com/maxliux5/limi/issues/new)，写清操作、预期和实际结果。截图先移除账号、会话内容等私人信息 |
| 给更多 agent 管理 skills、MCP | 参考已有资源页与适配器接口；兼容性和目录差异留在 [adapters](../packages/daemon/src/adapters)，不需要写 Calli 插件 |
| 接入另一个 agent | 从 [适配器接口](../packages/daemon/src/adapters/types.ts) 和现有实现开始，前端用 capabilities 表达差异 |
| 把外部工具的进度带进会话和看板 | 参考 [ext-loopx](../packages/ext-loopx)，实现独立工作数据源 |
| 做一个新的工作视图 | 参考 [ext-board](../packages/ext-board) 和 [ext-memory](../packages/ext-memory)，先作为内置包通过 PR 集成 |

## 独立数据源：从 LoopX 示例开始

1. 为一个真实工具写明使用场景，以及要显示的最少信息。先对照 [公开契约](../packages/extension-api) 与 [当前进程协议](loopx-integration.md)，不要照设计稿中未实现的接口直接开发。
2. 包含 `manifest.json` 与独立 `.mjs` 入口。声明名称、版本、权限、设置项、固定命令和工作数据源。当前外部包只支持工作数据源，不加载任意前端组件。
3. 实现依赖检测、设置校验和工作快照。用稳定工作项 ID，保留来源、完整性与更新时间；未知或部分结果不要假装为完整进度。由宿主管理命令执行、超时与线程关联。
4. 在本地目录安装验证，再打包为固定版本 `.tgz`。可参考 `npm pack -w @rah/ext-loopx`；本地路径在 daemon 所在机器解析，HTTPS 归档安装需要 SHA-256。包需要自带运行所需代码；宿主不会替包执行安装脚本或下载依赖。
5. 分享源码仓库、版本产物、权限说明、安装步骤和兼容范围。社区插件可以有自己的仓库；目前还没有自动收录的插件市场。

独立进程仍以 daemon 用户身份运行，并不是系统沙箱。接入前如实声明命令的副作用，只使用宿主提供的受控接口。

## 新视图：保持统一，也保持克制

内置视图只依赖 [extension-api/web](../packages/extension-api/web.d.ts)；通过宿主拿数据、导航和组件，不直接导入 web 或 daemon 的私有实现。内置包仍需注册进目录并随 Calli 构建，不能当作普通外部包安装。

先显示概况，展开时才加载重详情；异常、未知与过期状态直接可见。复用宿主颜色、控件和手机布局，避免每个插件各画一套界面。桌面点击与键盘、手机触摸都应能访问同样的信息。

## 提交前

- 新接口、适配器行为与失败路径有测试；适配器的行为补到假 agent。
- 检查安装、停用、卸载、权限和断线状态。不要把测试数据或私人配置带进提交。
- 界面在桌面与手机尺寸、亮色与深色下检查。文案补齐中文、英文、日文。
- 运行 `npm run typecheck && npm test && npm run build`；官网改动另跑 `npm run test:site`。

更完整的原则见 [AGENTS.md](../AGENTS.md)。后续方向见 [TODO](TODO.md)，扩展设计见 [extensions-design.md](extensions-design.md)。BotMux 提醒、通用任务控制等尚未实现，可先在 issue 中讨论需求。
