# 交接方式与验证

交接关系保存在 hub 数据库的线程 `handover` 中，新增 `mode: continue | branch`。不改 agent 的原生会话或配置，不迁移旧数据。

- 运行中手动交接默认「新开会话」（branch），来源继续运行；选择「停下原会话，接着做」（continue）时先验证目标，再停止当前轮，停止成功后创建接手线程。
- 已停会话默认接力，仍可选择新开会话。自动交接和额度用完卡片的一键接手显式使用 continue。
- daemon 统一计算有效方式：没有 mode 的旧关系按 branch；continue 来源在交接之后又启动新轮，也按 branch。新关系保存来源事件边界 `sourceSeq`，避免同毫秒事件的先后歧义；无边界的 continue 按创建时间比较。读取不改写存储方式。
- 只有有效 continue 合并侧边栏、历史与输入目标。branch 保持两个独立会话，接手行保留交接图标；交接记录保留来源导航并标出「接力 / 分出去」。中间关系变化时丢弃已加载的旧祖先视图，避免继续显示不属于本条接力链的历史。

`POST /api/threads/:id/handover-thread` 接受可选 mode；省略时由 daemon 按来源当前运行状态选默认值。非法方式返回 400。线程列表与详情返回有效 mode，前端只消费结果。目标无效时不停止来源；来源无法及时停止时返回 409，不创建接手会话。

## 验证范围

- daemon/API：方式写入、默认值、显式停止、非法参数和目标；旧记录推导；来源恢复后推导为分出去而原始数据不变；中间关系独立推导；branch 历史不隐藏交接正文；自动交接方式。
- Web 单元测试：只沿接力关系归组、选择输入目标与构建历史缓存标识。
- Chromium：运行中默认新开、来源继续运行、两个会话各自发送与侧边栏独立显示；已停默认接力、合并历史及早段输入投给接手方；来源另开一轮后界面实时解除接力；显式停止后接力；额度报错卡片请求 continue。
- 四组合截图在 `packages/e2e/shots/handover-mode/`：`running-dialog-*`、`branch-sidebar-*`、`branch-history-*`、`continue-source-*`、`resumed-source-*`（desktop/phone × light/dark）。已实际查看 Chromium 截图；手机为触控尺寸模拟，未测实体手机。协议执行使用假 agent，未另跑真实付费模型。
