# 自动接力与手动交接

交接关系保存在 hub 数据库的线程 `handover` 中，使用 `mode: continue | branch`。不改 agent 的原生会话或配置，不迁移旧数据。

- 手动交接一律 branch：无论来源运行中还是已停，新会话拿交接内容独立开始。弹窗无方式选择，来源不停、两个输入框各发给所看的会话。
  - 阅读时，来源没有再启动新轮、也没在运行，看来源的人往下滑会接上这条手动交接的会话（只读快照，分隔线写明「手动交接 · 来源 → 新会话」，下面是折叠的交接内容）；来源之后又启动了新轮、正在运行，或用户取消了这次接力，两边就是各自独立的会话，不再接上。
- 自动交接（额度接近上限/耗尽、协作成员自动接手）与额度报错卡片的一键接手显式使用 continue。这类接力合并正文：各段仍是独立会话，聚合在最新会话下。同实例换模型沿用原线程与模型分隔行。
- **老段不再因为继续对话而脱离链（2026-11-18 起）**：在老的一段单独发消息，不会把它从聚合里拆出去。daemon 的有效方式只看 `mode` 和 `detached`；来源在交接之后自己又开的轮次叫「后续」，由 `handover.followups` 计数（`sourceSeq` 之后、非 hub 发起的 `turn.started`，接回之前为止），不改写存储。从最新段看合并正文时，老段只读到交接那一刻（`sourceSeq`），它的后续不混进主线，只在那段末尾留一行「交接之后「标题」另有 N 条后续 · 进入查看」，点开是那一段的完整独立阅读（单段视图）。
- 侧边栏始终聚合所有交接关系：最新会话在上、「N 个会话」展开。只保留 agent 图标与状态点，链卡片保留前后叠放图标；分叉、工作树、交接与定时来源作为悬停文字，不占列表行。顶部交接记录保留来源导航，标出「自动接力 / 手动交接」。
- 主控交接时协作随之迁移，旧段在协作记录里是退休成员；侧边栏仍把它们当作主控自己的会话列进交接链（`ownRows`），不当成员藏起。链与协作同在时一张卡片两个折叠：先是交接链，再是子智能体，折叠行前分别标交接与子智能体图标（同概况看板）；子智能体按领着协作的那一段取，不一定是卡片正面那段。展开的交接链每行显示那一段自己的标题（去掉自动加的「（接手）」后缀，改过名就显示新名），agent 只用图标表示，名字放悬停提示。截图脚本 `packages/e2e/chain-team-shots.mjs`。
- 正文加载只沿有效 continue。中间关系改变时清除旧祖先缓存；侧边栏聚合不影响输入发送目标。

## 界面（方案 C：分界细线 + 看到哪段发给哪段）

- **段间细线**：合并正文里每段开头一条 hairline，线上是 agent 图标 + 该段标题 · agent · 时间（浅色小字，无底色无边框），点标题切到那一段单独继续。线下保留原来的「接手自 X · 额度用完 · 摘要 N 字 ›」折叠行。
- **浮出细线**：往上滑进入更早一段、且那段自己的分界线已滚出视口时，顶栏下方浮出同样的细线，右端 ↓ 回到最新段。它是零高度的 sticky 层叠在正文上，不挤动布局，也没有整条提示栏。
- **输入目标由正在看哪段决定**：最新段时输入区只有输入框和发送；看到更早一段（滚动进入，或点进老会话）时消息发给那一段，输入框左下角一个安静的标记「[图标] 发给 X ×」（× 回到最新段），placeholder 变成「继续「段标题」…」。手机上输入框折叠时标记也留着。判断「正在看哪段」是视口上方三分之一处所在的段，由 `MergedHistory` 滚动监听上报。
- **概况看板的「接力」组**：顶栏概况最上面，摘要「N 段」，行样式同子智能体行：agent 图标、段标题、右侧状态（最新段「当前」、正在看的「正在看」，其余显示 agent 名；运行中、待处理沿用原有颜色）。点行切到那段。只有链里 ≥2 段才出现，数据用已有线程列表（`handoverGroups`），不新增请求；折叠/展开沿用概况原有规则。
- 顶栏不加分段胶囊；去掉了「前段只读 · 取消这次接力」条和输入框表头，「取消这次接力」仍在线程菜单的交接记录里。

## 交回老对话（做法 2）

A → B → … 链的最新一段要交接时（自动额度交接、额度报错卡片、消息菜单「自动交接」、手动交接弹窗），如果链里更早某段能接回，就问用户：

- 「交接到老对话「A 的标题」」：不新建线程，在 A 原来的线程和原生会话里继续。A 收到一轮：自 A 离开后各段做了什么的摘要（复用现有摘要写法：源 agent 能写就写，否则压缩 agent，最后日志整理，内含接力链大纲）加失败那一轮和排队消息，由 `# 交回` 开头。队列、协作席位随之移到 A。
- 「交接到新对话」：新建线程，只带摘要，method 为 summary，不走 resume 复制。
- **可接回的条件**（`AutoHandover.returnTargets`）：那段在链上且未归档、有原生会话 id、没在运行或等待、agent 不是当前这段的 agent、agent 已连接且没被隐藏、没被拉黑、有新鲜额度读数且窗口都低于阈值、权限级别能保持；同一线程只记录一次接回，已接回过的不再提供。不满足就只有新对话。
- **自动交接**无人在场：倒计时卡片下一行两个安静的选项，有可接回的老对话时默认选老对话（用户嫌交接段太多）；倒计时结束时重新校验，老对话已不能接回就退到新对话（新对话目标也不可用才停下），按当前选择执行。有老对话可选时不走 resume 复制，两条路都带摘要。
- 手动入口：额度报错卡片多一个「交接到老对话「标题」」主按钮（原来的「交给 X 接手」降为次要，即新对话）；消息菜单「自动交接」和手动交接弹窗里多一行「交接方式」。

### 存储形态

关系只在 hub 数据库，不改 agent 的目录、配置和原生会话文件，旧记录不迁移：

- `threads.handback`（新增列，JSON，可空）：`{ sourceId, afterSeq, sourceSeq, at }`，记在被接回的 A 上。`sourceId` 是交回时的链头 B；`afterSeq` 是 A 自己接回前最后一个事件的 seq；`sourceSeq` 是 B 在交回时最后一个事件的 seq。B 的 `handover.sourceId` 仍指向 A，不改。
- 一个线程因此有两段：`afterSeq` 之前是链里「A（交出前）」，之后是「A（接回后）」。合并正文顺序是 A（交出前，读到 B 的 `handover.sourceSeq`）→ B（读到 `sourceSeq`）→ 分界线 →  A（接回后）。接回后 A 的首轮（交回提示）和别的接手段一样折叠成「交回自 X · 摘要交接 · N 字」。
- 历史接口：`GET /history?chain=1` 对有 handback 的线程自动只给 `afterSeq` 之后；`&part=before` 读它交出前的部分（配合 `before=` 截到交接点）。`GET /history/handover` 对应返回交回卡片（`method: 'return'`）。
- 遍历防环：daemon 的 `chainSegments` 与 web 的 `chainEntries` 每个线程最多访问两次（接回过的才有两段），A→B→A 或坏数据互相接回都会终止；web 的 `latestHandoverThread` 把「接回前交给别人的边」不算作续接，所以 A 接回后仍是链头，A 之后再交接出去则 A 又成为父节点。
- 局限：同一线程只记一次接回；接回后再从 A 交接出新对话没问题，但再次交回 A 不提供。

## 参考与取舍

- Claude Code `/compact` + fork：压缩自己的会话继续，或 fork 出新会话；我们的「新对话」只带摘要像 `/compact` 的产物，不复制原生会话，「老对话」像回到被 fork 的父会话。
- LibreChat 的 fork：分叉出来的是独立对话，父子之间不合并阅读；我们要的是各段独立又能合并滑动，所以用细线分段而不是切换面板。
- OpenCode 的父子会话：子会话挂在父会话下、可以进入单独对话再回来；对应这里「点标题切到那一段单独继续」和「看到哪段发给哪段」。
- 取舍：不做分段胶囊或标签栏（顶栏不增控件），不另起提示条，输入目标跟着阅读位置走并用一个小标记说明；接回只记在被接回的线程上，不拷贝历史，也不改 agent 的会话。

`POST /api/threads/:id/handover-thread` 默认 branch；自动调度及一键接手显式传 continue。非法方式返回 400。此接口不停止来源。线程列表与详情返回 daemon 计算的有效 mode、`followups` 与 `handback`，前端不自行推导运行事实。

`POST /api/threads/:id/takeover` 增加可选 `returnTo`（链上老线程 id）：不在 `returns` 里返回 409，通过则交回。`GET /api/threads/:id/auto-handover` 增加 `returns`（可接回的老对话，近的在前）；`PATCH` 接受 `choice: 'return' | 'new'`（只在倒计时提供选项时有效，否则 409）；视图的 `returnTo`、`choice` 描述当前倒计时。
