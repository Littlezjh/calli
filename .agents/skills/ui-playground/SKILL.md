# UI Playground

改 UI 不许只出一版。先做 playground 让人挑，挑完再写进组件。这条对手机和桌面都成立。

## 为什么

同一句话两个人脑中的画面不同，文字描述选不准设计；截图又只能看不能摸。
一个 10 分钟的静态页，能让人在**自己的手机上、深浅两种主题下**摸到每个方向的间距、层级和手感，比来回描述快得多，也符合 AGENTS.md 第 3 条「先参考再动手」：playground 里并排的差异本身就是对比分析。

## 怎么做

1. **先查参考**（AGENTS.md 三条原则之三）：每个方向对应一个同类开源项目的做法，一句话写在 playground 里，让取舍有据可查。
2. **建目录** `/tmp/<feature>-playground/`：`index.html` + 复制仓库的 `packages/web/src/styles.css`（用真 token，看到什么将来就长什么样）。
3. **做 2–4 个方向，整界面体验**：顶部一排 tab 切换方向，切过去后**整个界面**按该方向渲染（顶栏、正文、排队、输入框、浮层都要像真的），让人在自己手机上摸到完整手感——不是页面里塞几个小卡片。每个方向配一句设计意图和参考出处；第一段放「现状」作对照；哪个方向有倾向就标「推荐」，但让用户做最终决定。
4. **必须能选**：每个方向一个「选这个」按钮，POST 到本地服务记录到 `choice.log`；用户点完回一句话，读日志定案。没有选择机制的 playground 是白做。
5. **页面要能滚动**：仓库的 styles.css 把 `html, body` 锁成 `overflow: hidden`，playground 必须在行内样式里覆盖回 `overflow: visible !important`，否则手机上下拉不动。
6. **顶部放切换**：方案 tab + 亮/暗 + 宽/窄，四组都要能看；交互美（手势、长按）用 pointer 事件真做出来，不要只画样子。
7. **起服务并验证**：`nohup node` 单文件静态服务，绑定 hub 同 IP 的空闲端口，记下 PID；起完用 e2e 的 `launchBrowser` 无头打开一次，确认渲染、滚动、按钮都工作，再发链接。
8. **发链接给用户**，附两张无头截图的文件路径（回复里写单个文件的完整路径才能点开）。

## 收尾

- 用户选完：读 `choice.log`，按所选方向实现，提交后**按 PID 关掉服务**、清掉临时目录可留可删。
- 换方向很快：改 HTML 存盘即生效，服务不用重启。
- Playground 是临时产物，**不进仓库**；最终样式从 playground 抄进组件时去掉 `pg-` 前缀类名，用真实的 i18n 和图标。

## 反例

- 只贴截图问"哪个好"——看不清交互和手机手感。
- 一版直接进组件——用户不满意就返工，比 playground 贵。
- 忘了解锁滚动——用户手机上拉不动，等于没做。
